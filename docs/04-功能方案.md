> 配套文档：`01-总体技术方案.md`（架构与库表）、`02-接口文档.md`（接口契约）、`03-前端设计.md`（页面与组件）
> 编制日期：2026-09-19

## 二、功能编号规则

`模块码 - 两位序号`，编号一经确定不再变更，后续需求追加只增不改。

| 模块码 | 模块名 | 说明 |
|---|---|---|
| USR | 用户与认证 | 注册登录、个人中心、偏好 |
| DST | 目的地管理 | 目的地、景点 |
| RTE | 路线与行程 | 路线、行程明细 |
| INT | 互动 | 点赞、收藏、预约、评论 |
| PLN | 自主规划 | 用户自建行程 |
| AIC | ★ AI 智能推荐 | 意图解析、召回、重排、生成 |
| RAG | ★ AI 旅游问答 | 知识库、检索、问答 |
| INS | ★ 数据洞察与大屏 | 统计、AI 洞察、可视化 |
| SYS | 运营管理 | 轮播图、反馈、用户、配置 |

优先级：**P0** 必做（缺了系统跑不起来）/ **P1** 应做（体现完整度）/ **P2** 可选（时间富裕再做）

| AIC-10 | **降级兜底**：LLM 超时或失败时自动切换规则推荐并提示用户 | 系统 | P0 | — | 返回 `source: RULE_FALLBACK` |
| AIC-11 | 一站式推荐（意图 + 召回 + 生成合并为一次 SSE 调用） | 用户 | P2 | `/ai/recommend` | `POST /ai/recommend/one-shot` |
| AIC-12 | AI 调用限流与配额控制（按用户 / 全局） | 系统 | P1 | — | Redis 令牌桶 |

> AIC-02 与 AIC-06 是**两次独立的 LLM 调用**，职责不同：前者做「理解」，后者做「排序 + 解释」。分开的好处是意图可以被用户看见和修正，避免黑盒。
> AIC-08 支持用户在流式输出中「停止生成」，已输出内容保留。

## 六、开发排期建议（按功能而非按时间）

| 批次 | 目标 | 包含功能 | 里程碑 |
|:--:|---|---|---|
| 第 1 批 | 能登录、能看到数据 | USR(P0)、DST(P0)、RTE(P0-P1)、SYS-01/02 | 首页与路线详情可正常浏览 |
| 第 2 批 | 能互动、能规划 | INT(P0)、PLN(P0) | 点赞收藏预约评论 + 规划编辑器跑通 |
| 第 3 批 | **核心创新点** | AIC(P0)、RAG(P0)、INT-13 | 一句话生成行程 + 问答带引用 |
| 第 4 批 | 运营与可视化 | INS(P0)、SYS-06/07/08/09 | 大屏上线 + 配置可调 |
| 第 5 批 | 完整度与打磨 | 全部 P1 | 后台页面补齐、异常兜底、演示数据 |
| 第 6 批 | 加分项 | P2 功能 | 导出、地图分布、AI 辅助填行程 |

> **风险提示**：第 3 批是全项目最大风险点，建议在第 2 批完成后**先单独打通一个最小的 LLM 调用链路**（输入一句话 → 返回一个 JSON），把模型接入、密钥管理、超时重试、降级四件事验证掉，再往上叠业务。
