# 业务流程与业务规则

> 由 `04-功能方案.md` 第五至第十章拆分而来，是所有模块的**行为契约**。
> 开发节奏：先在 [`04-功能方案.md`](04-功能方案.md) 确认「做什么」，再到本文确认「怎么表现」。
> 业务规则编号（`BR-模块-序号`）可被代码注释与测试用例直接引用。

## 一、核心业务流程

### F1 · AI 智能推荐（★ 主流程）

```
用户在 /ai/recommend 输入自然语言
        │
        ▼
① 前置校验：输入长度 ≤ 500 字；Redis 校验用户 AI 配额
        │ 超限 → 返回 429「今日 AI 用量已满，请明天再试」
        ▼
② LLM 意图解析（AIC-02）
        │ 解析失败 / JSON 不合规 → 重试 1 次 → 仍失败则走规则解析（正则 + 关键词词典）
        ▼
③ 返回意图卡片，用户可修改标签 / 天数 / 预算（AIC-03）
        │
        ▼
④ 多路召回（AIC-04）
   ├─ Item-CF：基于用户-路线行为矩阵，取相似用户偏好路线
   ├─ 内容相似：目的地 + 标签 + 天数 + 价格的余弦相似度
   ├─ 热度：近 30 天浏览/收藏/预约加权
   └─ 行为：用户近期浏览过的同类路线
        │ 四路按配置权重融合 → 去重 → Top 50
        ▼
⑤ LLM 语义重排（AIC-06）
        │ 候选路线摘要拼装成 Prompt → LLM 输出 Top5 + 匹配分 + 推荐理由
        │ 失败/超时 → 降级：直接按融合分返回 Top5，reason 用模板生成（AIC-10）
        ▼
⑥ 展示推荐结果（含匹配度、命中标签、理由）
        │
        ├─ 用户点「生成详细行程」→ ⑦ SSE 流式生成（AIC-08）
        │      逐字推送 Markdown 行程单，支持「停止生成」
        │
        └─ 用户点「以此创建规划」→ 跳转 PLN-01
```

**分支与异常**

| 场景 | 处理 |
|---|---|
| 需求过于模糊（「推荐一下」） | 意图解析返回空字段，前端展示补全引导：「请补充目的地或天数」 |
| 召回结果 < 3 条 | 放宽价格区间与天数 ±2 后重召回，并在结果页提示「已为你放宽条件」 |
| LLM 首 token > 8s | 前端提示「正在努力生成」，超过 120s 断开并提示重试 |
| 用户中途离开页面 | 前端 AbortController 中断，服务端检测断连后停止生成 |

### F2 · 自主规划（PLN）

```
入口：/plan/create 空白创建  或  以某条路线为模板  或  从 AI 推荐结果一键创建
        │
        ▼
① 填写标题、出发日期、目的地（可多个）、天数、预算、人数
        │ 目的地确定后自动生成 N 天空框架（按天数拆分）
        ▼
② 逐天编辑：从景点库选择 / 手动添加行程项
   ├─ 拖拽调整天内顺序
   ├─ 跨天拖拽移动行程项
   └─ 实时计算预算占用，超支时进度条变警示色
        │
        ▼
③ 保存前本地校验：≥1 天、每天 ≥1 项、预算 > 0、天数 ≤ 30
        │
        ├─ 保存草稿（status=0）→ 可在列表中继续编辑
        └─ 正式保存（status=1）
        ▼
④ 可选：点「AI 优化」，LLM 检查节奏与顺序，返回建议清单（含优化后行程）
```

### F3 · 预约流程（INT-04 / 05 / 06）

```
用户在路线详情页点「立即预约」
        │
        ▼
① 选择出行日期、人数、填写联系人
        │ 校验：日期 ≥ 明天；人数 1-10；同用户同路线同日期不可重复预约
        ▼
② 名额校验：该路线该日期的已确认人数 + 本次人数 ≤ 路线名额上限
        │ 超出 → 返回 2002「该日期名额已满」
        ▼
③ 生成预约单（bookingNo 规则 BK + yyyyMMdd + 3 位流水），status=0 待确认
        │ 同时触发：写 user_behavior、更新路线 bookingCount
        ▼
④ 管理员在后台审核 → status=1 已确认 / status=2 已取消
        │ 状态变更后 30 天内可标记为 status=3 已完成
        ▼
⑤ 用户在「我的预约」可取消（仅 status=0/1 可取消），取消后释放名额
```

### F4 · 评论与情感分析（INT-07 / 13 → INS-06）

```
用户发表评论
   │
   ├─ 前置：敏感词过滤（INT-14）→ 命中则拒绝并提示
   ├─ 前置：每人每路线每天最多 3 条（BR-INT-05）
   ▼
入库（status=1 显示）
   │
   ▼ 异步（@Async，不阻塞用户响应）
LLM 情感分析 → 写回 comment.sentiment / sentiment_score
   │ 分析失败 → 标记 sentiment='unknown'，由定时任务补偿重试（最多 3 次）
   ▼
定时任务聚合 → 供 INS-06 情感环形图 + 负面关键词
   │
   ▼
推荐侧：某路线负面评论占比 > 30% 时，热度分 × 0.8 降权
```

### F5 · RAG 问答（RAG-01 ~ 05）

```
用户提问
   ▼
① 语义检索：问题向量化 → Milvus Top-K（K=5）召回知识片段
   │ 最高相似度 < 阈值 → 不调 LLM，直接返回「知识库暂无相关内容」（RAG-05，防编造）
   ▼
② 上下文拼装：命中的目的地/路线/攻略片段 + 系统提示词 + 最近 3 轮对话
   ▼
③ LLM 流式生成（SSE）
   ├─ 先推送 references 事件（引用来源，供前端渲染跳转 Chip）
   └─ 再逐 token 推送回答正文
   ▼
④ 落库：会话消息、token 消耗、命中来源
```

### F6 · 大屏数据刷新与 AI 洞察（INS-09 / 15）

```
每日 02:00 定时任务（INS-15）
   ▼ 预聚合近 30 日指标 → 写入 statistic_daily 表
   ▼
读取聚合结果 → 拼装洞察 Prompt → LLM 生成自然语言判断（INS-09）
   ▼ 结果存 ai_insight 表（按日期唯一）
   ▼
大屏加载时：
   ├─ 指标卡 / 图表 → 读预聚合表（60s 轮询）
   ├─ AI 洞察 → 读当天的 ai_insight（每日只生成一次，可手动重生成）
   └─ 实时动态 → SSE 长连接推送
```

## 二、状态机与枚举

### 2.1 用户 `sys_user.status`

| 值 | 含义 | 可流转到 |
|---|---|---|
| 0 | 禁用 | 1（管理员启用） |
| 1 | 正常 | 0（管理员禁用） |

禁用的用户登录返回 `1002`，已登录的 Token 校验时直接拒绝。

### 2.2 目的地 / 路线 `status`

| 值 | 含义 | 可流转到 |
|---|---|---|
| 0 | 已下架 | 1 |
| 1 | 已上架 | 0 |

下架后：前台列表与详情均不可见（返回 404），但已产生的收藏 / 预约 / 评论记录保留。

### 2.3 预约单 `booking.status`

| 值 | 含义 | 可流转到 | 触发方 |
|---|---|---|---|
| 0 | 待确认 | 1、2 | 管理员审核 / 用户取消 |
| 1 | 已确认 | 2、3 | 用户取消（限额内）/ 管理员完成 |
| 2 | 已取消 | —（终态） | — |
| 3 | 已完成 | —（终态） | 管理员标记 |

### 2.4 评论 `comment.status`

| 值 | 含义 | 可流转到 |
|---|---|---|
| 0 | 已隐藏（管理员） | 1 |
| 1 | 显示中 | 0 |

用户自行删除为逻辑删除（`deleted=1`），与隐藏区分开。

### 2.5 反馈 `feedback.status`

| 值 | 含义 | 可流转到 |
|---|---|---|
| 0 | 待处理 | 1、3 |
| 1 | 处理中 | 2、3 |
| 2 | 已解决 | —（终态） |
| 3 | 已关闭 | —（终态） |

### 2.6 规划 `user_plan.status`

| 值 | 含义 | 可流转到 |
|---|---|---|
| 0 | 草稿 | 1 |
| 1 | 已保存 | 0 |

### 2.7 情感 `comment.sentiment`

| 值 | 含义 | 说明 |
|---|---|---|
| positive | 正面 | score ∈ (0.6, 1] |
| neutral | 中性 | score ∈ [0.4, 0.6] |
| negative | 负面 | score ∈ [0, 0.4) |
| unknown | 未分析 | 分析失败的兜底值 |

### 2.8 提示词模板 `prompt_template.status`

| 值 | 含义 | 说明 |
|---|---|---|
| 0 | 停用 | 保留历史版本 |
| 1 | 启用 | 同一 `promptCode` 下**有且仅有一个**启用版本 |

### 2.9 推荐结果来源 `source`

| 值 | 含义 |
|---|---|
| LLM | 大模型正常参与（意图解析 / 重排 / 生成） |
| RULE_FALLBACK | 已降级为规则引擎，前端需展示提示 |

## 三、业务规则

### 3.1 USR

| 编号 | 规则 |
|---|---|
| BR-USR-01 | 用户名 4-20 位，仅字母数字下划线，全局唯一（忽略大小写） |
| BR-USR-02 | 密码 8-20 位，须同时包含字母与数字，存储用 BCrypt |
| BR-USR-03 | 邮箱 / 手机号全局唯一；邮箱验证码 5 分钟内有效，同一邮箱 60 秒内不可重复发送 |
| BR-USR-04 | Token 有效期：accessToken 2 小时，refreshToken 7 天 |
| BR-USR-05 | 偏好标签最多选 8 个；预算区间下限 < 上限；避雷标签最多 5 个 |
| BR-USR-06 | 埋点上报单次最多 50 条，超出丢弃并记录告警 |

### 3.2 DST / RTE

| 编号 | 规则 |
|---|---|
| BR-DST-01 | 目的地名称在同省份内唯一；经纬度必填且在合法范围（lng 73~136，lat 3~54） |
| BR-DST-02 | 封面图必填；标签最多 5 个；人均预算 ≥ 0 |
| BR-RTE-01 | 路线天数 = 行程明细的天数，两者不一致时禁止保存 |
| BR-RTE-02 | 每天行程项数量 1-15 条；行程项的时间点可选，选填时按排序展示 |
| BR-RTE-03 | 价格 ≥ 0；难度取值 1-5 |
| BR-RTE-04 | 删除目的地前校验：若存在关联路线，禁止删除（返回 409） |
| BR-RTE-05 | 人工推荐权重范围 0-100，默认 50；置顶路线在首页推荐位优先展示 |
| BR-RTE-06 | 已产生预约的路线不允许删除，只允许下架 |

### 3.3 INT

| 编号 | 规则 |
|---|---|
| BR-INT-01 | 点赞 / 收藏为幂等开关操作，同一用户对同一路线唯一 |
| BR-INT-02 | 预约出行日期须 ≥ 当前日期 + 1 天；人数 1-10 |
| BR-INT-03 | 同一用户对同一路线同一出行日期只能有 1 条未取消的预约 |
| BR-INT-04 | 预约名额校验：当日已确认人数 + 本次人数 ≤ 路线名额上限 |
| BR-INT-05 | 评论每人每路线每天最多 3 条；评分 1-5 整数；内容 5-500 字 |
| BR-INT-06 | 评论图片最多 3 张，单张 ≤ 5MB |
| BR-INT-07 | 回复层级最多 2 层（评论 → 回复），第 3 层折叠展示 |
| BR-INT-08 | 仅评论作者本人或管理员可删除 / 隐藏评论 |

### 3.4 PLN

| 编号 | 规则 |
|---|---|
| BR-PLN-01 | 规划天数 1-30 天；每天行程项 ≥ 1 条 |
| BR-PLN-02 | 出发日期须 ≥ 当前日期；预算 > 0 |
| BR-PLN-03 | 行程项的排序号 `sortNo` 在**同一天内**唯一且连续 |
| BR-PLN-04 | 规划上限：每个用户最多 50 条规划，超出提示删除旧规划 |
| BR-PLN-05 | 草稿状态不参与统计，不算作有效规划 |

### 3.5 AIC / RAG

| 编号 | 规则 |
|---|---|
| BR-AIC-01 | 输入长度 5-500 字；超长截断并提示 |
| BR-AIC-02 | LLM 结构化输出须通过 JSON Schema 校验，失败重试 1 次后降级 |
| BR-AIC-03 | 召回后交给 LLM 重排的候选数由配置决定（默认 50），上限 100 |
| BR-AIC-04 | 单用户 AI 配额：20 次/小时、200 次/天（意图 + 重排 + 生成合计）；全局兜底 2000 次/天 |
| BR-AIC-05 | 意图置信度 < 0.5 时，前端强制展开意图编辑卡引导用户确认 |
| BR-AIC-06 | 行程生成单次超时 120s；断连立即停止生成，不继续消耗 token |
| BR-AIC-07 | LLM 调用失败率 > 30%（5 分钟窗口）时，自动熔断并全量降级为规则推荐，10 分钟后半开探测 |
| BR-RAG-01 | 知识片段切片长度 500 字，重叠 50 字 |
| BR-RAG-02 | Top-K 默认 5；最高相似度 < 0.6 时判定无命中，不调 LLM |
| BR-RAG-03 | 上下文携带最近 3 轮对话，超出丢弃 |
| BR-RAG-04 | 回答禁止编造知识库外的行程与价格，Prompt 中明确约束 |
| BR-RAG-05 | 索引重建期间问答接口降级为「知识库维护中，请稍后再试」 |

### 3.6 INS / SYS

| 编号 | 规则 |
|---|---|
| BR-INS-01 | 所有统计口径以「自然日」为准，时区 Asia/Shanghai |
| BR-INS-02 | 大屏轮询 60s；同一管理员多端打开时共享缓存，避免重复聚合 |
| BR-INS-03 | AI 洞察每日 02:00 生成一次，按日期唯一；手动重生成会覆盖当天结果 |
| BR-INS-04 | 统计接口返回数据量限制：榜单 TOP ≤ 20，地域分布 ≤ 34（省级） |
| BR-SYS-01 | 轮播图最多 8 张启用中；排序号为整数，同值按创建时间倒序 |
| BR-SYS-02 | 4 路召回权重之和必须等于 1.0，否则禁止保存 |
| BR-SYS-03 | LLM 温度范围 0-1.5；候选集大小 10-100；每日配额 100-10000 |
| BR-SYS-04 | 提示词模板同一 code 同时只能有 1 个启用版本 |
| BR-SYS-05 | 提示词修改生成新版本，历史版本保留，支持回滚 |
| BR-SYS-06 | 管理员不可禁用 / 删除自己；系统内置 admin 账号不可删除 |

## 四、功能级权限矩阵（数据权限）

除 `01` 中的角色权限外，还需实现**数据归属校验**：

| 资源 | 普通用户可操作范围 | 校验方式 |
|---|---|---|
| 收藏 / 预约 / 评论 | 仅自己创建的记录 | Service 层比对 `userId` |
| 自主规划 | 仅自己的规划 | 同上，越权返回 403 |
| AI 会话与消息 | 仅自己的会话 | 同上 |
| 反馈 | 仅查看自己提交的反馈 | 同上 |
| 轮播图 / 目的地 / 路线 / 用户 / 配置 | 无权限 | `@PreAuthorize("hasRole('ADMIN')")` |
| 大屏与统计 | 无权限 | 同上 |

> **越权访问是毕设答辩最常见的追问点**：不能只在前端隐藏按钮，必须在 Service 层做归属校验。

## 五、非功能需求（功能可用性指标）

| 类别 | 指标 |
|---|---|
| 性能 | 首屏加载 ≤ 1.5s；普通接口 P95 ≤ 500ms；AI 首 token ≤ 3s；召回 + 重排总耗时 ≤ 3s |
| 并发 | 支持 50 并发用户在线；AI 接口并发限流 20 QPS |
| 可用性 | LLM 不可用时系统降级而非报错；关键接口失败重试 2 次 |
| 安全 | 密码 BCrypt 加密；接口越权校验；XSS 过滤；MyBatis 参数绑定防注入；**LLM 提示词注入防护（用户输入与系统提示词隔离）** |
| 合规 | AI 生成内容标注「内容由 AI 生成，仅供参考」；用户评论敏感词过滤 |
| 可维护 | 密钥与模型配置走配置文件 / Nacos；提示词走数据库可热更新；关键 AI 调用全量日志 |
| 可观测 | 接口耗时、LLM 调用成功率与 token 消耗、限流触发次数可查 |

## 六、验收标准（关键功能怎么算做完）

| 编号 | 验收标准 |
|---|---|
| AIC-02 | 输入「我想 10 月去云南玩 5 天，预算 3000 左右，喜欢自然风光和美食」，能正确解析出目的地=云南、天数=5、预算=3000、标签含自然风光与美食，置信度 > 0.8 |
| AIC-04 | 返回结果中包含各路召回候选数明细，总候选 ≥ 20 条 |
| AIC-06 | 每条推荐结果含 0-100 的匹配分与不少于 30 字的推荐理由，理由中至少提及 2 个用户输入的条件 |
| AIC-08 | 首次 token 在 3s 内到达；前端逐字渲染不卡顿；点击停止后 1s 内中断 |
| AIC-10 | 手动断开 LLM 服务地址后，接口仍返回推荐结果，`source` 字段为 `RULE_FALLBACK`，页面出现降级提示 |
| RAG-02 | 提问「十月去香格里拉要注意什么」能流式返回回答，且回答内容确实来自知识库文档 |
| RAG-03 | 每条回答下方展示引用来源，点击可跳转到对应路线 / 目的地详情 |
| RAG-05 | 提问知识库外的内容（如「今天上海天气」），返回明确的无命中提示而非编造答案 |
| INT-13 | 发表一条正面评论后 10s 内，`comment.sentiment` 变为 `positive` |
| PLN-02 | 能拖动行程项调整顺序并跨天移动，保存后重新打开顺序一致 |
| INS-09 | 大屏洞察文案包含当日实际数值，且至少给出 1 条可执行的建议 |
| INS-12 | 在 1366×768 与 2560×1440 两种分辨率下大屏均完整显示、无滚动条、无元素溢出 |
| SYS-08 | 调整权重滑块后立即重新推荐，结果排序发生可观察的变化 |
| SYS-09 | 修改行程生成提示词并启用后，下一次生成结果风格明显变化；回滚后恢复 |
