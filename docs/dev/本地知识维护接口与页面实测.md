## 新增契约

均需ADMIN；匿名HTTP401/普通用户HTTP403。统一业务错误HTTP200+body.code，批量有效请求外层code200，逐项结果另带code。

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/admin/ai/knowledge/health` | 所有未删除资料的total/enabled/disabled/indexReady/needsRebuild/sourceUnavailable/unlinked/searchable |
| GET | `/admin/ai/knowledge/page` | 原分页/标题/状态筛选，增加indexState=READY/NEEDS_REBUILD、sourceState=AVAILABLE/UNAVAILABLE/UNLINKED，可组合 |
| POST | `/admin/ai/knowledge/repair` | `{documents:[{id,expectedRevision}]}`，1—10项，不允许重复ID，每项独立事务 |

分页仍current=1—1000000、size=1—100；非法筛选400。列表增加actualChunkCount/indexState/indexIssue/sourceState，不返回正文。健康条件为LOCAL_NGRAM、indexedRevision=revision、实际分片非空且与记录计数一致、全部分片代次匹配。

异常原因：NOT_BUILT（待构建）、STALE_REVISION（元数据过期）、MISSING_CHUNKS（分片缺失）、COUNT_MISMATCH（分片计数错误）、CHUNK_REVISION_MISMATCH（分片代次不符）。这是元数据/分片结构检查，不是每个倒排词的内容校验或校验和检查。

AVAILABLE为独立攻略或当前公开来源；UNAVAILABLE含路线父目的地下架；UNLINKED为旧目录资料无sourceId，提示人工关联，不猜ID。沿用旧无关联资料可查看全文的兼容政策；UNLINKED不代表自动下架。sourceAvailable兼容字段保留。enabled不等于searchable，必须同时通过来源和索引检查。

最终86项报告中的真实请求（夹具已清理）：

```json
{"documents":[{"id":95,"expectedRevision":1},{"id":90,"expectedRevision":1},{"id":91,"expectedRevision":999},{"id":999999999,"expectedRevision":1}]}
```

HTTP200实际响应摘录（仅省略timestamp）：

```json
{"code":200,"message":"success","data":{"total":4,"succeeded":1,"unchanged":1,"failed":2,"results":[{"id":95,"code":200,"outcome":"REPAIRED","message":"本地索引已修复","revision":1,"chunkCount":1},{"id":90,"code":200,"outcome":"UNCHANGED","message":"索引已就绪，保留原有分片","revision":1,"chunkCount":13},{"id":91,"code":409,"outcome":"FAILED","message":"资料已被更新，请刷新后重新操作","revision":null,"chunkCount":null},{"id":999999999,"code":404,"outcome":"FAILED","message":"资料不存在或已删除","revision":null,"chunkCount":null}]}}
```

修复健康资料返回UNCHANGED并保持chunk ID；异常资料重建索引，REPAIRED；过期版本409、删除/不存在404，不影响已提交的其他项。ID/版本须JSON正整数，字符串/布尔/负数、空列表、超过10项、重复项或null元素均400，输入整体校验先于写入。修复停用资料和下架来源均不自动发布。原单篇“重建分片”仍是主动重建，健康跳过只适用于新增repair接口。

## 真实问题、原因与解决

| 问题 | 复现/原因 | 解决与验证 |
|---|---|---|
| 重复片段挤占来源 | 基线top5前两项同docId，另一相关文档未出现；按分片分数/id排序 | 先按覆盖率、正文命中词数、chunk ID排序，再优先不同文档；不足topK再补其他片段。最终前两项来自两篇预期资料 |
| 首片只有标题命中 | 同一标题词写到全部分片，文末实际相关片段和无关键词首片同分 | 同覆盖率下优先正文命中多的片段；基线首摘录不含“澄汐湖湾”，最终包含 |
| 缺分片仍可读全文 | 元数据仍LOCAL_NGRAM且版本匹配，原就绪判断忽略实际分片 | 共用真实分片结构判定；缺片/代次不符/计数不符归异常，公开全文404，重建后恢复 |
| 默认关闭邮箱仍健康DOWN | 未配置SMTP，MailHealthIndicator仍探测；日志确认Mail health check failed | management.health.mail.enabled沿用TRIP_MAIL_ENABLED开关；关闭邮件后真实健康UP，发送仍503，未预留验证码/配额 |
| 前端编译失败 | 新选择事件参数隐式any（TS7006） | 具名KnowledgeDoc[]处理器，生产构建通过；一次路径替换在trip-web使用仓库相对路径失败导致TS6133/7006仍在，纠正目录后成功 |
| 浏览器定位器三次失败 | label同时匹配combobox/listbox；输入被可见占位层遮挡；checkbox原始input隐藏 | 通过有对应combobox的选择器可见wrapper点击，勾选可见checkbox组件；实际用户控件操作，未force点击或伪造接口 |
| 邮件旧脚本默认端口不对 | 默认8087/6387隔离SMTP环境未运行，首请求连接拒绝，0项不能算通过 | [保留INCOMPLETE证据](evidence/email-auth/20261002-122654-http-disabled.json)，改在本批真实8080/6379工具验证默认关闭路径；未创建该失败脚本账号 |
| Redis SCAN空行误算为key | 扩展85/86实际keys=[""]，不是存在验证码 | 过滤CLI空行，最终86/86；不删除共享邮件键 |
| 证据口令脱敏遗漏 | 复用redactor只覆盖password，新增reset字段newPassword未覆盖 | 扩展oldPassword/newPassword脱敏，已产生的本批失败证据仅去除夹具口令并写redactionCorrection，保留所有断言/响应和失败状态 |

响应丢失后批量修复没有自动重发；用户刷新检查状态后操作，已健康项可跳过。异常修复替换chunk ID后旧会话引用可能失效，页面确认提示且私人历史回归通过。不自动启用资料/来源，不访问外部链接。

## 质量评估口径

[质量对比](evidence/knowledge-quality/retrieval-quality-comparison.json)由实际报告计算；基线5个问题，最终8个（增加来源下架等负例）。3个正例明确预期doc ID，另外检验无命中/停用/来源父级下架等负例。

- 正例平均预期来源Recall@5：0.8333→1.0。
- MRR@5：1.0→1.0，没有提升，不能宣称所有排序指标都改善。
- 文末关键词问题首摘录含查询：false→true。
- 200个候选分片上限、词法覆盖率阈值0.3和最多5片保持；多样性只在候选池内有效，不能保证大型库完整召回。

这是小规模可控词法夹具，不是人工标注的大样本语义评估、真实旅游推荐质量或生产压测。没有新增模型/向量、最近3轮上下文或问答token流。
