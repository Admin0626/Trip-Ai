# 建表对照清单（26 张表）

> 用途：用户自己写 `trip-server/src/main/resources/sql/schema.sql` 时的**字段对照与检查表**。本文件不替代 DDL，只负责把「每张表该有哪些字段、依据是哪份文档、哪里文档没写清」摆平。
>
> 基线：[`05-数据库设计.md`](../05-数据库设计.md) 为库表权威，[`api/01~05`](../api/) 为接口契约权威，[`08-业务流程与业务规则.md`](../08-业务流程与业务规则.md) 为行为契约权威。三者冲突处以本文件第七章的裁定为准。

## 标注约定

| 标记 | 含义 |
|:--:|---|
| ✅ | 文档明确写了，照抄即可 |
| ⚠️ | 文档没写全，我按接口契约推断，**你确认一下** |
| ❌ | 文档之间打架、或业务规则要求但无人给字段 —— **阻塞项，必须先定** |

## 一、开工前先定：9 个阻塞项

这几条不定，DDL 写不下去（或者写完必然返工）。

| # | 问题 | 冲突点 | 建议 |
|:--:|---|---|---|
| **B1** | `route.recommend_weight` 类型与量纲打架 | `05` §1.2 写 `decimal(5,4)`（最大 9.9999）；`BR-RTE-05` 写「范围 0-100，默认 50」 | 二选一。倾向 **`decimal(5,4)` 存 0-1**，因为 `recommend_config.recall.*.weight` 本来就是 0-1（`BR-SYS-02` 要求四路权重和 = 1.0），同一系统里两种量纲容易出错。选了就把 `BR-RTE-05` 改成 0-1 |
| **B2** | 评论点赞**没有落库的表** | `api/03` 有 `POST /interaction/comment/{id}/like`，但 `05` §1.1 定死 26 张表，里面没有 `route_comment_like` | ① 加第 27 张表 `route_comment_like`，`uk(user_id, comment_id)` 保证幂等（推荐，与点赞/收藏一致）；② 走 Redis Set 不落库（重启丢、无法反查谁点过）。**建议 ①** |
| **B3** | 情感分析失败要重试，没字段计数 | `08` F4 要求「失败标记 `sentiment='unknown'`，定时任务补偿重试最多 3 次」 | 加 `sentiment_retry tinyint unsigned not null default 0`（`05` 没写） |
| **B4** | 路线每日名额上限没字段 | `BR-INT-04` 要「当日已确认人数 + 本次人数 ≤ 路线名额上限」，`05` §1.2 的 `route` 字段表里没有 | 加 `quota_per_day int unsigned not null default 20` |
| **B5** | `user_plan` 缺 `destinationIds` | `api/03` 请求体是 `"destinationIds": [1, 2]`，`05` 完全没给 `user_plan` 的字段 | 加 `destination_ids varchar(255)` 逗号分隔（与 `route.tags` 的处理方式统一） |
| **B6** | 表名 `statistic_daily` vs `stat_daily` | `08` F6 写「写入 `statistic_daily` 表」，`05` §1.1/§1.6 与 `07` §1.3 都写 `stat_daily` | 统一 **`stat_daily`**，回头改 `08` F6 那一句 |
| **B7** | `prompt_template` 列名与「唯一启用版本」怎么落地 | `08` §2.8 / `BR-SYS-04` 说 `promptCode`；`05` §1.2 说列名 `code`。且要求「同一 code 下有且仅有一个 `status=1`」—— MySQL **没有 partial unique index** | 列名用 `code`；唯一键建成 `uk(code, version)`；「只有一个启用版本」在 Service 层用「先把同 code 的其它版本置 0，再置本版本为 1」（同一事务）保证 |
| **B8** | 预约「同用户同路线同日期只能 1 条未取消」无法用唯一索引表达 | `BR-INT-03`；MySQL 不支持带条件唯一索引（`status != 2`） | 用普通索引 `idx(user_id, route_id, travel_date)` + Service 层校验；**不要**把 `status` 拼进唯一键（一个用户取消后再约就冲突了） |
| **B9** | `destination.routeCount` 是冗余列还是实时 count | `api/02` 的 `/destination/page` 响应里有 `routeCount`，`05` 的 `destination` 字段表没有 | 加冗余列 `route_count int unsigned not null default 0`（与 `route` 的计数冗余字段风格一致），新增/下架路线时维护 |

## 二、建表约定检查点（照 `05` §1.4，逐条打勾）

| # | 检查项 | 说明 |
|:--:|---|---|
| 1 | 主键 | `id bigint unsigned NOT NULL AUTO_INCREMENT` |
| 2 | 字符集 / 引擎 | `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci ENGINE=InnoDB` |
| 3 | 审计字段 | 除纯关联表外统一带 `create_time datetime NOT NULL DEFAULT CURRENT_TIMESTAMP` 和 `update_time datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` |
| 4 | 逻辑删除 | 只加在 8 张表上：`sys_user` / `destination` / `route` / `route_comment` / `feedback` / `user_plan` / `llm_chat_session` / `knowledge_doc`。字段 `deleted tinyint NOT NULL DEFAULT 0` |
| 5 | 计数冗余 | `route` 的 `like_count` 等由业务侧维护，**不建触发器** |
| 6 | 唯一约束 | 点赞 / 收藏用 `uk(user_id, route_id)` 保证幂等 |
| 7 | 索引 | 所有外键列建普通索引；列表页筛选列（`status` / `destination_id` / `create_time`）建联合索引 |
| 8 | 金额 | 一律 `decimal`，**禁止 float/double** |
| 9 | 标签 | 逗号分隔 `varchar`，暂不建标签表 |
| 10 | 普通列默认值 | 字符串列一律给 `NOT NULL DEFAULT ''`，`text` 与 `datetime` 例外。**别留裸 NULL**，否则 MyBatis-Plus 返 null 会让前端字段消失 |
| 11 | 大小写敏感 | `utf8mb4_general_ci` 本身不区分大小写，正好满足 `BR-USR-01`「用户名唯一忽略大小写」。**别改成 `_bin` 或 `utf8mb4_0900_as_cs`** |
| 12 | 布尔语义 | 统一 `tinyint(1)`：`1` 是 / `0` 否。项目里不用 MySQL 原生 `boolean` |
| 13 | yml 联动 | `id-type` 必须是 **`auto`**（主键是 `AUTO_INCREMENT`，不是雪花）。写成 `assign_id` 会往表里插 19 位雪花 ID，跟 `data.sql` 的演示 ID 对不上 |
