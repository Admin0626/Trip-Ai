## 二、实现的功能与关键设计

### 2.1 点赞 / 收藏（INT-01/02/03）— BR-INT-01 幂等开关

- `POST /interaction/like` / `POST /interaction/favorite`：先查后增删，`route.like_count = like_count ± 1` **数据库侧原子加减**（禁止先读后算，防并发丢数）
- **唯一键兜底**：插入冲突捕获 `DuplicateKeyException`，归一为「取消」，返回最新计数
- 回显：`GET /interaction/like/{routeId}/status` + `RouteServiceImpl` 列表/详情联查
- `GET /interaction/favorite/page`：我的收藏分页，返回 RoutePageVO（RouteCard 复用）

### 2.2 预约（INT-04/05/06）— BR-INT-02/03/04

提交预约校验顺序：
1. 参数校验（DTO）：人数 1-10、联系人必填
2. `travelDate ≥ 明天`（`LocalDate.now().plusDays(1)`）
3. 同用户同路线同日期 `status IN (0,1)` 查重 → 命中抛 `BOOKING_DUP`
4. **名额校验 `SELECT ... FOR UPDATE` 行锁**（锁 route 行）→ 已确认人数 + 本次 ≤ `quota_per_day`，否则 `BOOKING_FULL`（防并发超卖）
5. 生成单号 `BK + yyyyMMdd + 3位流水`，`booking_count + 1`

- 取消：仅作者本人（越权 403）；仅 `status ∈ {0,1}` 可取消（2/3 抛 409），取消后 `booking_count - 1`
- 管理端审核：严格状态机 `0→1 / 0→2 / 1→3`，非法流转抛 409

### 2.3 评论（INT-07/08/09/10）— BR-INT-05/06/07/08

- 发表：每人每路线每天 ≤3 条（按 `createTime ≥ 当天 0 点` 计数，超限抛 `COMMENT_TOO_MANY`）；`parentId>0` 时校验父评论存在且为顶级（回复只到 2 层）；`comment_count + 1` + **全量重算 `avg_score`**（只统计显示中评论）
- 列表（公开）：支持情感筛选（`sentiment` 字段，第 3 批 AI 填充前的展示基础）、按时间/评分排序；VO 带昵称/头像/`liked`
- 删除：仅作者本人（越权 403）→ 逻辑删除 + `comment_count - 1` + 重算平均分
- 评论点赞：幂等开关，`route_comment.like_count ± 1` 原子加减

### 2.4 管理端（INT-06/12）

- `/admin/interaction/booking/**`：全部预约分页（状态/路线筛选）+ 审核
- `/admin/interaction/comment/**`：评论管理分页 + 显示/隐藏（`status 0/1`）
- `/admin/interaction/stat/{routeId}`：单条路线互动统计

### 2.5 验收中修复的问题

1. **`createBooking` 响应 `createTime: null`**：MySQL `DEFAULT CURRENT_TIMESTAMP` 不回填实体，改为 insert 前显式 `setCreateTime(LocalDateTime.now())`
2. **seed 数据冗余列不同步**：`data.sql` route 计数初始为 0，与明细表不一致 → 新增同步脚本并已对现有库执行，20 条路线全部对齐
