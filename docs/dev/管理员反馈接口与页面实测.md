## 本轮发现与修复的产品问题

| 编号 | 实际问题 | 原因 | 解决方案及验证 |
|---|---|---|---|
| FB-01 | 待处理可直接变已解决，处理中可原地覆写，已解决/已关闭还能以相同状态修改回复 | 服务端仅限制终态不能变为另一个状态，未实现业务规则§2.5的完整转换表 | 限制`0→1/3、1→2/3`，其他转换拒绝；终态回复不可改。验证所有终态目标及数据库回复不变 |
| FB-02 | 旧管理页面仍按“待处理”提交时，可覆盖另一管理员已经处理的回复 | 服务端读取最新状态当作更新条件，没有客户端读取时的前置状态 | 回复增加必填整数`expectedStatus`；不符返回409，SQL仍以原状态做CAS。旧页面、并发两请求均验证只有一个结果被接受 |
| FB-03 | `contact:123`被作为字符串接受并保存 | 联系方式缺少其他字符串字段使用的严格JSON反序列化 | 对contact使用严格Text解析，数字返回400；可选空值及100字符上限保持原语义 |
| FB-04 | 管理页打开待处理记录，默认状态为0，填写回复直接保存报400 | 对话框把当前状态赋给目标状态，但选项只支持1/2/3 | 待处理默认“处理中”，处理中默认“已解决”，只显示该来源的合法目标；终态仅查看、无保存按钮 |
| FB-05 | 管理员只能看到前20条，无法筛选和翻页；缺少联系方式及截图 | API已支持分页筛选，页面固定调用第一页，详情字段没有渲染 | 增加分页、状态筛选和刷新；显示联系方式、截图、上次回复时间；实际加载第二页并验证状态过滤 |
| FB-06 | 回复校验失败产生未处理Promise异常 | 页面只有finally恢复状态，未捕获请求层reject | 用户和管理页在加载/提交处catch，保留统一错误提示；冲突保留输入，最终pageerror=0 |

前端还限制重复提交、保护保存期间的弹窗操作；列表采用请求序号防止旧响应覆盖新筛选结果。后者为实现防护，本批没有专门注入乱序网络来验证所有时序。

|---|---|---|
| `PUT /admin/feedback/{id}/reply`，0→2 | HTTP200/code200，数据库变已解决 | HTTP200/code400，原行不变 |
| 0→1时缺少`expectedStatus` | HTTP200/code200 | HTTP200/code400 |

| 已解决再次提交status2新回复 | HTTP200/code200，回复被改写 | HTTP200/code400，已保存回复不变 |
| 普通用户访问管理列表/回复 | HTTP403/code403 | 保持HTTP403/code403 |
| 未登录提交/读取反馈 | HTTP401/code401 | 保持HTTP401/code401 |
| 不存在或逻辑删除的反馈回复 | HTTP200/code404 | 保持HTTP200/code404 |

成功回复示例：

```json
{"expectedStatus":0,"status":1,"replyContent":"正在核查问题"}
```

业务成功返回`{"code":200,"message":"success","data":null}`（另有timestamp）。校验、状态错误与冲突沿用项目HTTP200/业务400或409约定；权限在Security层使用真实HTTP401/403。

## 真实验收覆盖

- 用户ID取登录身份；我的反馈只包含自己的记录，额外传他人userId不改变范围。普通用户不能回复别人的反馈，也不能列出管理反馈。
- 标题/正文空白及长度、联系方式类型与长度、反馈类型、外部图片/目录穿越/null/超过3张、分页0/负数/超限/非整数均检查；四种合法类型和字段长度上限可保存。
- 回复空白、超长、字符串/浮点状态、缺失或非法前置状态均拒绝；回复后的管理员ID、时间、去除首尾空白、用户可见回复由SQL/GET核对。
- 状态流转逐项验证；逻辑删除行不能读取或回复；用户分页无重复；管理员状态过滤只返回目标状态。
- 同一待处理记录并发提交“处理”和“关闭”，最终一方200、一方409，数据库与胜出回复一致。两个请求竞争不等于生产负载测试。
- Edge真实上传PNG、提交反馈、管理员看联系方式/图、默认处理、另一旧标签页冲突后保留输入、用户看到处理中回复、管理员解决、终态只读、用户看到最终回复。
- 管理员20条/页、用户10条/页均通过真实第二页请求；普通用户前端后台路由受阻。文本中的`<script>`按文字显示，未把它作为HTML插入；这不代表完整XSS安全审计。
- 手机实际面板宽度和命中层级检查通过；[管理员弹窗截图](evidence/feedback/2026-09-27T15-01-46-324Z-final-browser/admin-reply-mobile.png)、[用户反馈截图](evidence/feedback/2026-09-27T15-01-46-324Z-final-browser/user-feedback-mobile.png)。

## 复现与兼容性

启动MySQL、Redis、后端和前端后：

```powershell
# trip-server，Python标准库；复用同目录password_acceptance.py的HTTP/脱敏工具
python scripts/feedback_acceptance.py --label final
python scripts/basic_user_acceptance.py
mvn test

# trip-web，已安装Edge与Playwright，可用PLAYWRIGHT_MODULE指定运行时
node scripts/feedback_browser.cjs --final
npm run build
```

数据库密码可用`MYSQL_PASSWORD`覆盖；脚本默认本地开发配置和`trip-server/uploads`。管理员回复新增必填`expectedStatus`，旧调用方需要同步修改；前端已随本批更新，无数据库迁移。单独反馈详情/删除/只改状态接口仍是设计条目，当前详情由分页返回完整字段，不宣称整个运营后台已完成。
