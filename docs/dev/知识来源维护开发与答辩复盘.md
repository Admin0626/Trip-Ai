# 知识来源维护开发与答辩复盘

2026-10-03。承接PR #5知识维护，独立codex/knowledge-sources，不接真实模型。实测详见[接口与页面实测](知识来源维护接口与页面实测.md)，进度见[交接](知识来源维护进度.md)。

## 解决的问题

管理员维护知识时，来源关联和正文编辑是两种操作。旧完整编辑会删除再建分片，不必要地改变历史引用ID；公开目录下拉又无法选择未公开来源，即便资料本身停用。本批提供单独关联操作和管理员目录摘要，完整编辑器也复用选择器。

用户路径：后台知识资料 → 调整来源 → 选择独立攻略/目的地/路线 → 名称查询或分页 → 核对名称/ID/公开状态 → 确认保存。停用资料关联隐藏来源后仍停用；启用资料不能关联隐藏目录。转独立攻略可能改变公开效果，因此确认文案明确说明解除目录公开状态限制。

## 代码链路与事务

`AdminKnowledgeController`类级ADMIN权限保护sources与{id}/source。`KnowledgeInput.Source`约束JSON真实整数、正数、类型枚举和必填expectedRevision，GUIDE/null及有效来源由服务做组合校验。

`KnowledgeService.sources`只返回目录摘要，分页20、上限50，关键词参数绑定并转义LIKE通配符。路线JOIN目的地，删除父级的路线不在候选中；未公开父级单独标记PARENT_UNAVAILABLE。没有把新查询加入用户公开接口。

`changeSource`一个事务：锁知识行 → 比对expectedRevision → 根据原status验证来源 → 相同关系返回UNCHANGED → 读取原索引READY → 更新docType/sourceId/revision/indexed_revision → 推进匹配旧版本的分片代次 → 返回当前资料。没有调用index，也不删除分片/词元；标题、正文、启用状态、FILE标记保持不变。并发实测一成功一409，不能以旧版本覆盖新来源。

原索引健康才把indexed_revision推进到新版本，异常则设0。原因是未来代次可能恰好等于新revision，仅保持旧元数据会意外通过就绪检查。这样来源操作不冒充索引修复；后续管理员显式修复。READY仍是结构检查，不代表倒排词逐项内容一致性已验收。

## 历史引用为何保留又更新

历史存docId/chunkId及当时检索快照，每次读取调用`activeReference`校验当前资料、索引结构和目录公开状态。来源更新不改正文、分片ID，因此历史可继续显示相同片段，链接取当前资料的sourceId。目录/父级下架时历史隐藏引用，全文404、检索排除；恢复可再显示保留的片段。

历史链接按当前来源动态展示，并非来源关系审计日志。没有新增来源变更审计表、目录版本快照或实时推送。已展示内容需要刷新；正常读取会执行当前来源检查，但本批不声称并发目录下架能撤回已经发出的HTTP字节。

## 前端职责

`KnowledgeSourcePicker.vue`为调整弹窗及完整编辑器共用。查询框与选择器分开，避免Element Plus重新展开触发remote空查询重置分页。原selected ID不在当前页时单独查询摘要；名称附ID和公开状态，父级隐藏路线可明确识别。加载版本号及卸载标记丢弃过期响应，异常显示可重试；后端仍负责最终状态校验。

`KnowledgeSourceDialog.vue`获取当前完整资料，保存时传打开时版本。确认期间禁用，409保留选项但要求刷新重开，400也保留输入。成功后父页面重新加载列表、清除旧选择并刷新健康统计。不自动重试、不自动启用、不自动修复异常索引。

## 答辩常见问题

- 为什么不是再建一张来源表？已有knowledge_doc的doc_type/source_id足以表达单一目录来源，本批无迁移；来源变更审计、多来源关系以后另行设计。
- 是否实现了RAG语义能力？没有，仍LOCAL_NGRAM本地词法检索；来源管理完善已有引用链路，不是向量或模型回答。
- 为什么用行锁还要传版本？行锁串行化同时写入，版本比对阻止管理员基于旧页面覆盖新结果，两者解决的问题不同。
- 是否会把隐藏资料公开？保存不修改status；启用资料必须关联公开目录。明确转GUIDE后不再受目录状态限制，管理员需确认，不能保证公开效果永远不变。
- 原资料无来源怎么办？保持兼容，通过筛选定位，管理员人工确认并关联，不猜测ID或批量改演示数据。
- 上线要改库吗？本批不需要；已有库仍需之前知识/会话/邮箱升级。不要重建schema或导入种子覆盖数据。
