## 接口契约与实际响应

新增登录接口 `POST /api/ai/planner/circuit`。请求与测试连接一样：`{connection:{baseUrl,model,apiKey}}`。Key仍须用于识别该连接，放在请求体，不放URL，不持久化。用户ID取认证主体，客户端无法选择他人状态。URL/模型/Key沿用严格校验。

最终证据中的OPEN状态data（时间字段见原始JSON）：

```json
{"phase":"OPEN","total":4,"failed":4,"failurePercent":100.0,
 "minimumCalls":4,"windowSeconds":60,"cooldownSeconds":4,
 "retryAt":"2026-09-28T14:57:37.599Z","retryAfterSeconds":4}
```

此时间来自本轮实际响应，原始JSON同时保存外层code/message/timestamp。业务错误沿用HTTP200：熔断/正在探测/状态不可用为code503，供应商故障为3004，额度不足为429，非法连接为400；匿名状态接口HTTP401/code401。状态查询不访问模型、不扣额度、不生成模型日志，但会清理过期窗口样本或处理过期探测。

## 实际验证范围

- **故障与触发**：HTTP401/429/500、超时、空choices、超过1MiB、非法行程结构。每次外呼为一个样本，非法结构通常两次；低于最小样本不会开放。七成功+三失败的30%保持CLOSED，第十一调用失败后4/11>30%开放。
- **拦截边界**：OPEN的连接测试和行程生成共享状态；localhost/127.0.0.1、尾斜杠、Key首尾空白归一后仍被同一熔断拦截。比较真实上游计数、usage小时used和today.operations，均不增加。不返回假预览。
- **隔离**：改变Key、模型、基础路径、另一个实际上游端口，以及另一个用户，各有独立状态；同一用户总配额仍共享。
- **恢复**：实际等待短冷却后健康调用关闭；失败探测重新冷却。八个独立redis-cli客户端并发准入只有一个获探测，随后真实HTTP看到HALF_OPEN且拒绝调用。这里验证的是共享Redis并发门禁，**没有启动八个后端实例或进行生产负载测试**。
- **中断与过期**：实际等待探测租约到期后OPEN；旧成功不能关闭、旧失败不能重开已恢复的状态，靠代次及探测ticket判定。额度拒绝发生在探测预留之后，释放预留且不新增样本，额度恢复可立即再试。
- **结构探测**：半开输出不合格计一次失败并重新开放；第二次结构重试在熔断准入处code503，真实外呼/额度/操作数仅各+1。
- **状态可靠性**：真实Redis向专用样本写入超过60秒的历史score后，窗口将其删除；这项是时刻注入，不是等待60秒。检查TTL、空查询不分配key、故意破坏专用状态后安全503且无新外呼。Redis连接失败另用单测异常注入验证，没有停止共享Redis。
- **基础推荐**：8080默认熔断后实际调用规则intent/match成功，模型额度和模型操作统计保持不变。
- **页面**：OPEN倒计时及按钮禁用/到期恢复、HALF_OPEN提示与禁用、探测崩溃后的刷新/恢复、生成两天预览且不自动保存、连接切换清预览和状态、缓冲真实状态响应后切Key丢弃旧结果、Key未持久化、离页清Key、免费推荐导航、390px无横向溢出。

## 复现与清理

先保持MySQL3306、Redis6379、正式后端8080/api和前端5173运行。无SQL迁移。Maven编译会触发正式服务DevTools重启，必须等健康UP再测试。

独立终端在trip-server启动隔离后端：

```powershell
mvn spring-boot:run '-Dspring-boot.run.jvmArguments=-Dspring.devtools.restart.enabled=false' '-Dspring-boot.run.arguments=--spring.ai.model.chat=none --server.port=8081 --trip.ai.timeout-seconds=2 --trip.ai.circuit.window-seconds=60 --trip.ai.circuit.cooldown-seconds=4 --trip.ai.circuit.minimum-calls=4 --trip.ai.circuit.probe-lease-seconds=4 --trip.ai.circuit.key-prefix=trip:test:circuit:batch20260928 --trip.ai.quota.key-prefix=trip:test:quota:circuit20260928'
```

```powershell
# trip-server，隔离服务健康后
python scripts/circuit_acceptance.py --base http://localhost:8081/api --label final --prefix trip:test:circuit:batch20260928 --quota-prefix trip:test:quota:circuit20260928
# 另开终端，浏览器与默认检查需要受控服务
python scripts/circuit_acceptance.py --serve --port 11436
# 正式8080仍使用默认设置
python scripts/circuit_default_acceptance.py
# 原协议页面使用另一个受控服务
python scripts/user_planner_acceptance.py --serve --port 11435
```

```powershell
# trip-web
node scripts/circuit_browser.cjs
node scripts/user_planner_browser.cjs
npm run build
# trip-server
python scripts/user_planner_acceptance.py
python scripts/ai_quota_acceptance.py
mvn test
```

Edge脚本通过Playwright转发真实API响应到8081，没有合成响应体；缓冲真实状态响应仅用于旧响应测试。可用PLAYWRIGHT_MODULE指定运行时，MYSQL_PASSWORD覆盖本机密码。重复执行会创建新的时间戳证据。脚本仅删除明确创建的用户、审计、会话、用户配额/熔断key；不清全站生产quota计数、不清Redis数据库。共享默认全站计数仍包含实际测试外呼，等自然日重置。测试结束已关闭本批8081/11435/11436进程，清掉唯一隔离全站quota key，现有8080仍健康UP，见[最终清理](evidence/circuit/final-cleanup.json)。
