# 模型熔断与恢复：进度、目标、问题

更新：2026-09-28。本批起点 `9a2f2f5`，指令“继续下一批”。沿用实际测试、记录问题/原因/方案、开发复盘、提交推送的授权。

## 目标与实现约定

- 用户自定义模型连接增加 Redis 共享熔断；按用户、规范化地址、模型、Key 摘要隔离，不存明文 Key/地址/提示词。
- 5分钟滑动窗口，失败率严格大于30%触发，10分钟冷却后仅允许一个半开探测；增加默认10次最小样本以避免偶发单次失败即停用。
- 每次实际外呼计样本，结构重试也计；熔断拦截不消耗配额、不伪造外呼日志。输入、配额错误不算模型故障。
- 半开成功恢复，失败重新冷却；租约与代次防止进程中断或过期响应破坏恢复。模型失败不生成虚假行程，用户可转基础规则推荐。
- 页面展示状态、剩余等待时间、刷新与基础推荐入口，连接信息改变后重新核对状态。

- 不接真实收费模型；受控 OpenAI 兼容服务只能验证协议和故障流程，不能证明真实模型质量。
- 不重建数据库，不改现有账号会话；测试只创建/清理本批夹具，Redis使用显式SCAN，不使用旧Windows CLI静默失效的 `--scan`。
