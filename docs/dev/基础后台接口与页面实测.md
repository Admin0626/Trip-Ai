## 实际接口覆盖

- 匿名与普通用户分别验证目录、轮播、预约、评论、用户和AI日志的读权限；普通用户直接发送写请求均为HTTP403，匿名为HTTP401。
- 目的地新增、修改、名称重复409、严格类型/坐标400、关键词分页、上下架、删除关联路线保护；中文名称经HTTP写入和读取一致。
- 景点新增、编辑、门票持久化、状态非法值、公开隐藏与删除；公开接口不返回下架景点。
- 路线创建、详情、整套行程替换、天数/时间点/价格校验、置顶与权重；伪造ID、创建人和计数不会修改服务器字段。
- 下架路线和父目的地后，公开详情/每日行程/评论、互动写入及轮播隔离；管理员仍可读内容、处理历史预约和评论。
- 有预约的路线删除返回409，有路线的目的地删除返回409；移除测试关联记录后删除成功，数据库逻辑删除字段为1。
- 轮播新增/修改/启停/删除，目标与图片地址、开始/结束时间、排序和启用上限；未来/过期/下架目标隐藏，启用满8张时第9张返回400。
- 用户关键词/状态分页仅返回账号投影；禁用后access和登录被拒，恢复后旧access/refresh不会复活；管理员账号受保护，严格状态类型及分页上限被验证。
- 并发登录与停用共享用户行锁：登录可能先成功也可能返回1002，但停用完成后已签发会话不能访问；测试保存的是状态结果，不保存JWT。

### 关键实际响应

以下省略动态timestamp和测试ID，完整请求、响应见JSON证据。

| 请求 | 实际HTTP / 业务code | 含义 |
|---|---|---|
| 普通用户写 `/admin/user/{id}/status` | 403 / 403 | 服务端拒绝越权 |
| 数字轮播标题更新 | 200 / 400 | 请求体格式错误，不隐式转字符串 |
| 删除仍有关联路线的目的地 | 200 / 409 | 先处理关联路线 |
| 下架路线的历史预约确认 | 200 / 200 | 历史业务仍可管理 |
| 下架目的地的关联路线点赞 | 200 / 2001 | 路线不存在或已下架 |
| 停用普通用户后读取个人资料 | 401 / 401 | 现有会话失效 |
| 尝试停用管理员 | 200 / 409 | 管理员账号受保护 |

注意区分HTTP状态和业务状态。业务校验失败使用统一响应的code，不应只看HTTP200判断成功。

## 本轮发现、原因与解决方案

| 编号 | 复现与原因 | 解决方案和验证 |
|---|---|---|
| B01 轮播标题数字被接受 | 基线发送`title:123`返回200；默认JSON标量转换允许数字变为字符串 | title/imageUrl/linkType/linkValue采用严格字符串反序列化；同请求最终400 |
| B02 评论管理缺少显示状态 | 管理分页返回评论，但VO没有status，后台无法判断隐藏/显示 | VO及组装返回status；页面可以隐藏、恢复，实际SQL与浏览器均验证 |
| B03 下架路线历史管理被阻断 | 管理员审核预约/隐藏评论复用了“必须上架”的路线加锁方法，基线返回2001 | 分离历史记录加锁与公开可操作校验；后台使用存在性检查，仍保持行锁和预约状态/名额检查 |
| B04 公开评论漏了路线可见性 | commentPage只按评论自身status筛选，下架路线及下架父目的地的评论仍返回200 | 先验证路线及父目的地已上架；最终2001，后台分页仍可访问 |
| B05 互动漏了父目的地状态 | 点赞和预约只校验路线status，父目的地下架后仍可新增互动 | 公开读检查父目的地；互动写锁定路线及父目的地后检查状态；基线200改为2001 |
| G01 用户管理缺失 | 8项基线失败来自接口未实现及其后续断言，不是8个不同的旧代码bug | 新增账号投影分页和普通用户启停；撤销会话、保护管理员、严格类型，最终实际验收通过 |

新增管理入口时同步加固：预约/评论分页和状态过滤范围、严格整数状态、登录与账号停用的行锁协调、启停时撤销Redis会话。禁用失败会保留可重试错误，不靠前端隐藏按钮保障权限。

## 浏览器流程与测试问题

Edge实际操作：管理员登录→目的地新增/上架/编辑/图片上传→景点新增/编辑→路线两天行程创建及顺序调整→重新打开和编辑→置顶→轮播发布与首页链接→下架路线→确认/完成历史预约→隐藏/恢复评论→停用/启用用户→日志空状态→普通用户访问后台被拦截→390px手机弹窗→轮播编辑/停用/删除。后台退出入口另加实际退出和再次访问跳转检查。

首次47项浏览器断言通过，但人工查看截图发现截图发生在弹窗进入动画中，形成文字重叠的半透明画面；这是证据采集时序问题。脚本增加等待遮罩和子动画完成、白色背景断言及禁用截图动画，后续48项通过且人工查看手机截图正常。初次截图仍保留，不把它描述为产品始终半透明。

前后端启动最初遇到Maven缓存目录写入拒绝、Vite子进程spawn权限限制；使用获准的本地运行权限后恢复。一次在仓库根目录执行npx导致ENOTCACHED，改在trip-web使用已有依赖完成检查，没有安装新依赖。这些是运行/命令问题，不归为产品接口缺陷。

## 清理与复现

新脚本只使用自动注册的临时普通用户/管理员，以及返回的目的地、景点、路线、轮播ID；清理对应数据库行、Redis会话和上传文件，失败时也会保存检查和执行清理。旧第2批回归使用本机演示管理员登录，创建的3个测试账号、路线等已清理，额外核对其Redis会话已为空。未重新初始化表，未删除现有业务内容。上传文件名及绝对父目录经过检查。

启动MySQL、Redis、前后端后运行：

```powershell
cd trip-server
python scripts/admin_acceptance.py --label final
python scripts/password_acceptance.py --label final
python scripts/basic_user_acceptance.py
mvn test
# 在另一个终端的trip-web目录
node scripts/admin_browser.cjs
node scripts/feedback_browser.cjs --final
npm run build
```

MySQL密码通过`MYSQL_PASSWORD`覆盖本机开发默认值；浏览器运行时可用`PLAYWRIGHT_MODULE`指定。新后台脚本限制本地测试地址。证据对密码和JWT脱敏；AI日志页面不展示提示词、Key和原始模型内容，运行服务日志不纳入Git。
