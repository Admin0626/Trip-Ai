## 已实现接口

下表路径均相对/api。普通业务错误沿用HTTP200+响应体code；鉴权失败实际HTTP401/403，必须同时检查HTTP状态和body.code。

| 方法/路径 | 权限 | 实际行为 |
|---|---|---|
| GET /admin/ai/knowledge/page | ADMIN | current默认1，size默认20且≤100；标题keyword≤100字符，status=0/1；不返回正文 |
| GET /admin/ai/knowledge/{id} | ADMIN | 正文和revision、indexedRevision、indexMethod、chunkCount等 |
| POST /admin/ai/knowledge | ADMIN | 新建并事务分片；title/docType/content/status，可选sourceId；新增不得携带expectedRevision |
| PUT /admin/ai/knowledge/{id} | ADMIN | 同上述字段，携带expectedRevision；旧版本或缺版本409 |
| PUT /admin/ai/knowledge/{id}/status | ADMIN | {expectedRevision,status}；版本+1，匹配的本地索引同代更新 |
| DELETE /admin/ai/knowledge/{id}?expectedRevision=N | ADMIN | 逻辑删除文档，物理清理其分片/倒排词；缺版本400，旧版本409 |
| POST /admin/ai/knowledge/rebuild | ADMIN | {id,expectedRevision}，重建单篇本地分片；不是向量重建 |
| POST /admin/ai/knowledge/upload | ADMIN | multipart：file、title、docType默认GUIDE、status默认0、可选sourceId；UTF-8 TXT/MD |
| POST /ai/knowledge/search | 登录USER/ADMIN | {query,topK?}；topK默认5，范围1—5；返回原文片段和经验证的站内来源 |
| GET /ai/knowledge/documents/{id} | 登录USER/ADMIN | 仅公开且当前索引就绪的完整来源、更新时间、版本；不可用404 |

title≤200、正文≤20000、query为2—200个Unicode字符。正文先去开头BOM、统一CRLF/CR为LF、去首尾空白，拒绝非法Unicode和除LF/TAB外的控制字符。严格拒绝数字字符串、浮点/布尔整数及溢出关联ID。GUIDE不得填写sourceId；新增/编辑DESTINATION/ROUTE必须有真实关联ID，启用时还须公开。旧演示文档关联ID为空，重建保持原样，不按标题猜测目标。

保存示例：

```json
{"title":"步行攻略","docType":"GUIDE","sourceId":null,"content":"霁澜秘境适合清晨步行。","status":0}
```

查询示例：

```json
{"query":"霁澜秘境","topK":5}
```

实际返回结构：code=200，data包含query、mode=LOCAL_NGRAM、matched、message、references；每条reference含docId/chunkId/chunkIndex/title/excerpt/keywordCoverage/documentPath/sourcePath。documentPath为/knowledge/{docId}，sourcePath仅在关联来源有效时为/destination/{id}或/route/{id}，独立资料为null。具体ID及完整实际body见最终JSON，没有伪造固定ID。

无匹配返回code=200、matched=false、references=[]和明确提示；有公开资料但全部未建成当前本地索引时code=503、data=null。停用/删除/过期资料读详情404。已停用路线或其父目的地的关联资料，即使知识文档自身仍启用，也不参与检索和详情。

## 覆盖的关键场景

实际SQL检查500个Unicode字符、50字符重叠及CHAR_LENGTH一致，emoji不被拆开；200字符emoji标题/20000字符emoji正文被接收，45个分片持久化；超界、控制字符、无效代理项拒绝。中文二元组与全角英文NFKC查询有效，topK上限与稳定排序有实际断言；keywordCoverage为词法覆盖率，不是语义相似度。

文档编辑替换旧分片，状态切换保持内容代次；过期索引排除并可重建。两个同时携带同版本的真实PUT只有一个200、另一个409；过期版本编辑、启停、重建和删除均409。旧CRLF正文重建时同步规范化正文/版本，确保全文和分片偏移一致。

真实multipart验证大小为256KiB的文件成功（正文首尾空白清理后仍满足正文上限）；262145字节、PDF、非UTF-8、空文件、NUL、20001字符正文均400。文件只提取正文，sourceType=FILE，不保存文件路径或访问URL。

Edge使用真实登录及按钮操作验证：默认停用新建、启用公开、检索原文、全文跳转、远程选择关联目的地及实际详情导航；编辑时另一请求先提交，当前保存返回409且保留输入，关闭再打开取新正文；重建、实际文件导入、停用后消失/详情错误、普通用户后台重定向、确认删除。HTML样式原文只作为文本展示，没有img元素或脚本执行。

## 所有发现的问题、原因与方案

| 问题 | 原因 | 解决与验证 |
|---|---|---|

| 初次两轮52/54中，停用后期待200无匹配却得到503，随后脚本取null报错 | 唯一就绪资料被停用，其他10篇都未索引；这是正确维护分支，测试条件不完整 | 添加无关就绪夹具，将维护/正常无匹配分开；116/116，再扩展129/129。[首次](evidence/knowledge/20260929-210337-930237-initial.json)、[第二次](evidence/knowledge/20260929-210403-282331-expanded.json) |
| 重编译期间一次1/2，register响应无法解析 | Spring DevTools重启窗口发起HTTP验收，服务尚未稳定 | 等Maven结束及健康UP再执行；后续完整通过。[环境失败](evidence/knowledge/20260929-210932-234399-visibility-fixed.json) |
| 手机375px完整来源页横向溢出，初次Edge41/42 | 新增第6项导航后窄屏单行总宽超过可用宽度 | ≤640px导航3列2行，≤980px页头可换行；375/390/768px及44/44复测通过。[失败](evidence/knowledge/2026-09-29T13-12-53-010Z-initial-browser/results.json) |
| 非法Unicode测试使证据写入器抛UnicodeEncodeError并阻断账号清理 | ensure_ascii=false让未配对代理项进入UTF-8写入 | 写入前仅将不可编码字符转合法JSON转义；按保存证据恢复2个所属账号/会话，最终129/129包含服务拒绝非法Unicode。[45项RUNNING片段](evidence/knowledge/20260929-211925-942605-final.json)、[恢复](evidence/knowledge/interrupted-recovery.json) |

| 代码审查发现旧CRLF全文与规范化分片偏移可能不一致 | 重建若只规范化分片而不更新原文，Unicode偏移对应不到详情原文 | 重建在同一事务更新规范化全文，内容改变才版本+1；实际旧CRLF SQL夹具重建到8/8通过。属于审查后验证，不声称线上已出现事故 |
| 管理列表SQL来源可用字段为数值，与前端布尔类型不一致 | JDBC直接输出SQL表达式结果 | 返回前转boolean，管理列表真实HTTP与页面均通过 |
| Windows证据读取默认GBK报UnicodeDecodeError | 辅助检查忘记指定UTF-8；证据文件本身正确 | 所有新脚本文件/JSON读写显式UTF-8；重新读取成功，不属于接口故障 |

已有Vite主包大于500kB提示保留，未通过调高阈值隐藏。没有发现未处理的浏览器异常或未解决的本批功能失败。

## 复现与清理

已有库在MySQL客户端先执行：

```sql
USE trip_llm;
source D:/demo_series/Trip-AI/trip-server/src/main/resources/sql/upgrade_local_knowledge.sql;
```

不要在已有数据上执行schema.sql或data.sql。启动沿根README，等健康UP。管理员可逐篇“重建分片”；本机开发可运行下面的种子初始化脚本，它仅处理与仓库种子完全一致的10篇，修改过的种子跳过，不发布任意文档。

```powershell
cd trip-server
python scripts/knowledge_seed_index.py
python scripts/knowledge_acceptance.py --label final
mvn test
# 另一个终端从仓库根目录
cd trip-web
node scripts/knowledge_browser.cjs final
npm run build
```

测试需要本机MySQL权限创建专属夹具，密码由MYSQL_PASSWORD覆盖，不写入证据；Playwright可通过PLAYWRIGHT_MODULE指定本机包，实际使用msedge。脚本仅清理自己创建的知识/目录/账号、Redis会话和本人AI状态；不重建库、清共享Redis或更改正常用户资料。业务改动保留演示种子的持久本地索引，所有时间戳失败证据保留。

本批没有验收真实模型、嵌入/Milvus、语义相似度≥0.6、/ai/chat聊天上下文或token SSE；不把词法覆盖率阈值0.3当作原设计的语义阈值。
