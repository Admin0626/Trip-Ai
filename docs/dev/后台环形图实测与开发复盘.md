# 后台环形图：实测、问题与开发复盘

2026-10-08，在独立分支 `codex/analytics-donut` 实现。入口 `/admin/analytics`，ADMIN权限沿用现有后台。

## 已实现与数据口径

预约当前状态、全站模型调用结果改为环形饼图。中心显示总数；外侧引导线显示比例；图例同时显示分类、数量与占比，支持鼠标及键盘聚焦。趋势、目的地热度柱状图、路线价格散点和明细继续保留。

`Analytics.vue`调用现有`GET /api/admin/analysis/dashboard`，将`bookingStatuses`和`aiStatuses`转交`AnalyticsDonut.vue`。组件使用原生SVG的`stroke-dasharray`/`stroke-dashoffset`绘制圆弧；弧长按未舍入的`count / total`计算，文字显示1位小数。没有新增图表库、后端API、SQL迁移或模型调用。

- 预约占比：分母为当前时间、目的地筛选范围内预约总单数。统计按创建时间，分类是这些预约目前的状态；不是当天取消动作，也不是出行人数。
- 模型占比：分母为全站窗口内`llm_call_log`行数，目的地筛选不影响。可能包含重试，不代表计费或用户操作次数。
- 有记录时零类别显示0.0%，不画扇区。总数0时只有中性背景环和“暂无记录”，图例数量0、比例“—”，不将0/0画成0%或100%。
- 单一非零类别显示完整100%圆环。显示比例四舍五入，合计可能99.9%/100.1%，不修改实际数据凑满100%。
- 当前仅用于固定4个预约状态和2个模型结果，不作为任意大量类别的通用图表；分类固定排序保证颜色稳定。窄容器圆环/图例垂直排列，保留13px以上的实际比例文字尺寸；ResizeObserver退出时断开，数据更新时清空选中状态，尊重减少动效设置。

## 答辩复盘

可解释为“后端先计算真实分类统计，前端再把数量换算成弧长与比例”。例如21/40=52.5%，圆环对应未舍入的52.5%周长；图例保留21单以便核对。环形图适用于少量分类的整体构成，柱状图适用于目的地数量比较，折线适用于日期变化，散点适用于每条路线价格与预约量的分布。

演示路径：管理员打开数据与可视化，30日查看两张环形图；选择西安看单一类别100%；选择大理看零值；回到全部目的地，再切7/90日观察统计窗口变化。通过Tab聚焦图例或扇区，详细文字同步显示数量和占比。

进度见[后台环形图进度](后台环形图进度.md)。新功能分支提交并建立PR后等待用户授权合并；Excel统计导出、AI洞察、全屏运营大屏仍未提供。
