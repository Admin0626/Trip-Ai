## 新接口契约与真实响应

统一返回R信封；业务错误通常HTTP200 + code400/404/409，认证HTTP401/403。以下摘录保留实际字段；成功正文省略处明确标注，完整响应见证据，不是模型输出。

`GET /admin/ai/knowledge/sources`仅ADMIN。docType只能DESTINATION/ROUTE，current默认1、1—1000000，size默认20、1—50，keyword≤100 Unicode字符，sourceId可按正整数精确查找。关键词LIKE参数绑定并转义%/_/=。返回未删除目录的摘要，停用也显示；路线父目的地被删除时不显示。摘要字段只有id/name/status/available/parentName/availabilityReason，不公开完整目录正文。未登录401、普通用户403已实测。

实际请求`docType=DESTINATION&sourceId=91`：

```json
{"code":200,"message":"success","data":{"current":1,"pages":1,"records":[{"id":91,"name":"KS_c6549aac未公开","status":0,"available":false,"parentName":null,"availabilityReason":"UNPUBLISHED"}],"size":20,"total":1}}
```

路线有效但父目的地停用，available=false、availabilityReason=PARENT_UNAVAILABLE；同名条目保留不同ID。23+条目录夹具真实分页、第二页、字面通配符、已删除精确ID返回空记录、非法范围/类型均验证。

`PUT /admin/ai/knowledge/{id}/source`仅ADMIN，JSON参数docType=GUIDE/DESTINATION/ROUTE、sourceId正整数或null、expectedRevision必填正整数且拒绝字符串/小数/溢出。GUIDE须null；其余必须有效目录ID。按当前资料status检查：启用要求目录及路线父目的地公开；停用允许未公开但未删除来源。

真实`PUT /admin/ai/knowledge/97/source`：

```json
{"docType":"ROUTE","sourceId":373,"expectedRevision":1}
```

实际成功投影（document其他字段包括原title/content/updateTime等，见完整JSON）：

```json
{"code":200,"data":{"outcome":"UPDATED","document":{"id":97,"docType":"ROUTE","sourceType":"FILE","sourceId":373,"status":1,"revision":2,"indexedRevision":2,"indexMethod":"LOCAL_NGRAM","chunkCount":2,"vectorStatus":0}}}
```

标题、正文、FILE标记、启用状态、分片ID/偏移/内容与倒排词逐项比对未变化，分片代次移到2。再次发送相同关系、expectedRevision=2，outcome=UNCHANGED、revision仍2；持旧版本1即使关系相同也返回：

```json
{"code":409,"message":"资料已被更新，请刷新后重新操作","data":null}
```

GUIDE携带sourceId返回400“独立攻略无需关联ID”；目的地/路线缺ID返回400“目的地或路线资料须选择关联ID”；启用资料关联未公开/删除目录返回400“关联内容不存在或未公开，请先恢复内容或将资料停用”；资料不存在/已删除返回404。失败后版本未变；并发两请求同版本实测一200一409、版本仅加一次。

原异常索引来源调整后indexedRevision=0，仍须显式修复，不会借来源更新把未来代次、错代次或错误分片数伪装成就绪。健康资料不重建；已损坏资料的分片也不重建，既有索引修复接口仍能修复。

## 可见性与页面实测

旧非GUIDE但sourceId为空的资料，只在管理员明确选择后关联，不猜测种子ID、不批量改写。enabled状态保留。转为GUIDE会解除目录公开状态限制，保存前明确确认，不能描述成“公开效果一定不变”。

先保存私人检索历史，再关联路线：刷新历史仍使用相同chunk ID、当前sourcePath=/route/373。父目的地下架后检索不含原文、全文404、历史references=[]且unavailableReferenceCount=1；恢复父级后保留分片的引用可再次显示。目录删除同样隐藏。转独立攻略后历史sourcePath=null。源内容公开状态每次读取核验；已展示页面需刷新，无实时下架推送。

页面：调整来源弹窗、独立名称查询、20项分页、ID区分同名、选中来源不在第一页时按ID加载；启用资料不可选择隐藏项，停用资料可选择父级隐藏路线。普通全文编辑器复用该选择器。选中后来源下架仍由后端拒绝，输入保留；409保留选择并提示关闭/刷新重开，不自动重试。确认期间禁用表单，关闭请求失败不产生未捕获页面错误。桌面/375/768截图已人工查看。

## 所有问题、原因、方案

| 问题 | 原因/证据 | 解决与验证 |
| --- | --- | --- |
| 原编辑器不能选择停用来源；只改来源也重建正文 | 本批开始的源码核对：使用公开目录接口、完整save会调用index；未声称有旧版本HTTP失败基线 | 新ADMIN摘要分页、停用选择和source-only接口；124项/31项及44项回归 |
| 异常索引可能碰撞下一revision变就绪 | 实现审查发现：仅把同代次推进，未来indexed_revision/分片代次可能等于新版本；不是基线实测失败 | 先读取原READY；异常索引设indexed_revision=0，未来/错代次及计数异常SQL夹具实测 |
| Python预检SyntaxError | 同一行以逗号串联赋值，错误行18；首次py_compile未通过 | 改独立赋值语句，编译后执行实测 |
| 初测7/8目录唯一约束 | 夹具同省同名违反destination.uk_province_name，非产品接口bug | 同名夹具采用不同省；124/124，首次失败保留 |
| 页面来源第二页被重置 | 下拉重新展开触发remote空查询，search将current设1 | 改独立名称输入/查询按钮，选择器不隐式发查询；31/31覆盖第二页 |
| 页面初测监听到原始全量34而非筛选24 | 加载原始列表和查询重叠，监听只按path | 独立查询按钮待初始加载结束后操作，最终正确24 |
| 两次RUNNING报告，9项后进程退出 | 确认默认按钮“确定”，脚本定位“确认”；响应等待先拒绝造成未处理Promise，finally未执行 | 正确可见按钮定位、响应Promise附拒绝处理；原报告保持RUNNING并单独记录INCOMPLETE与恢复，不改成完整成功 |
| 首次恢复失败并误重跑旧脚本 | Python子进程未指定UTF-8，GBK解码中文输出失败，后续修正步骤未执行；PowerShell仍执行下一行 | 明确UTF-8，按专属ID及前缀逐项核验后清理两批，恢复文件保留原因与0残留 |
| 旧页面回归三轮33/34 | 第1轮已启动的旧脚本期待原标签；第2轮新changed调用缺GET参数；第3轮has内部定位器包含dialog祖先、相对作用域不成立 | 脚本改独立查询与新标签、明确GET、使用相对角色匹配；最终44/44，三份失败保留 |
| 详情请求失败可能未捕获、确认期间可重复提交 | 本批审查发现的边界，非已观察线上bug | open捕获错误，确认期间禁用表单，后端行锁/CAS仍兜底；最终pageerror=0，未声称独立网络故障注入已验收 |
| 既有主包超过500kB提示 | UI依赖主包较大，与来源API正确性无关 | 不扩大本批范围；构建通过并记录约1129.01kB |

所有成功、失败与中断证据保留，没有用成功报告覆盖失败。原日志可能含认证/SQL敏感数据，保持忽略；证据只保存脱敏响应。

## 复测与启动

原有数据库无需本批迁移。不要执行schema.sql/data.sql重建库。后端JDK21运行现有Java17目标，JAVA_HOME指向D:/Java/jdk-21.0.2，Maven启动参数保持spring.ai.model.chat=none；MySQL凭据由MYSQL_PASSWORD本机配置，Redis6379。

```powershell
python trip-server/scripts/knowledge_sources_acceptance.py --label final
node trip-web/scripts/knowledge_sources_browser.cjs final
```

脚本仅支持本机应用，SQL夹具需本机开发库权限。确认MySQL3306、Redis6379、后端8080/api、Vite5173已运行；页面入口/admin/ai/knowledge。邮件默认关闭，未接真实SMTP、真实模型/向量；本批不自动建立真实演示资料的来源关系，也没有生产负载/大语料验收。
