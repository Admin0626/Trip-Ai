# 用户自带模型：取消每日调用上限

2026-10-03，用户明确要求去掉额外每日次数限制。本批同时取消个人每日、全站每日限制，保留每小时调用限流（默认20）、同用户单请求、全站并发8、超时、熔断及地址校验。

## 行为与部署

- AiQuotaService只读`llm.quota.user.hourly`和当前用户小时计数；Lua原子校验/递增仅处理小时窗口。连接测试、普通生成、SSE和结构重试共用该准入路径。
- usage保留daily/globalDaily字段以兼容字段访问，明确enabled=false，其他值均null；hourly为enabled=true。每日计数不是改成巨大上限，而是不再读取或递增。
- 页面只根据小时remaining禁用操作，不再显示个人/全站每日余额或重置时间；标题改为“调用状态”，说明服务商计费和小时限流含义。今日操作成功/失败统计保留。
- 新初始化种子不再创建每日限制配置；已有数据库的两个旧配置无需删除，旧Redis每日键无需重置，应用不再读取。无需数据库迁移或重建。部署需同步更新前后端。
- 本地8080后端已按原chat=none启动方式重启并启用新实现；5173前端已验证。没有真实模型付费调用，也未更改现有用户数据或共享每日计数。

真实HTTP中临时用户旧日计数置200，连接测试、普通生成和两次无效结构尝试共4次外呼均进入可控服务，旧日计数保持200。小时20次用尽后仍code429，且不外呼、不伪造操作日志。规则推荐不计小时调用；usage明确每日不受限，认证/隔离/审计字段检查保留。3个临时账号、会话、个人Redis状态和测试日志均按专属身份清理。

只使用本地可控服务，不代表真实模型质量验证；未重跑全套SSE生命周期或其他无关后端接口。旧浏览器回归脚本已适配当前入口和控件文字，本批未执行该旧脚本；浏览器证据来自当前应用实际页面验证。历史配额证据保留原样，以本记录及更新后的API合同为准。
