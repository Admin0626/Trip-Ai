## 已实现接口契约

均以`/api`为后端前缀，需登录；用户ID取认证主体，传入userId不能改变归属。管理员也只能访问自己的资料会话。错误归属、不存在、已删除或LEGACY会话统一业务404。认证失败HTTP401，业务校验失败沿现有约定为HTTP200 + body.code=400/404/409/503。

| 方法 | 路径 | 参数与结果 |
|---|---|---|
| GET | `/ai/chat/session/page` | current默认1、size默认20/最大50，keyword可选≤100字符；只列本人LOCAL_SEARCH，按更新时间/id倒序 |
| POST | `/ai/chat/session` | `{title?}`；省略/空白用“新资料会话”，显式标题≤100个Unicode字符 |
| GET | `/ai/chat/session/{id}` | 本人详情：id/title/mode/revision/messageCount/时间 |
| PUT | `/ai/chat/session/{id}` | `{title,expectedRevision}`；成功版本+1，过期版本409 |
| DELETE | `/ai/chat/session/{id}` | 必填正整数expectedRevision；逻辑删除会话并物理清理其消息 |
| GET | `/ai/chat/message/page` | sessionId、size默认20/1—50、可选正整数beforeId；返回records/hasMore/nextBeforeId |
| POST | `/ai/chat/search` | sessionId、query(2—200 Unicode字符)、topK(默认5/1—5)、小写规范UUID requestId |

整数参数不接受JSON字符串、小数、布尔值；标题拒绝控制字符及不合法Unicode，query沿用本地知识规范化。默认会话首个问题自动生成前20个Unicode字符的标题，自定义标题不覆盖。100个活动会话/每会话200轮上限；一轮恰好2条消息，tokensUsed=0。无命中也保存一次真实检索结果。

历史消息id倒序选取size+1判断hasMore，页面内按id正序展示；下一页使用最早id作为beforeId，避免新消息插入造成offset重复。size=1的逐页验收收齐8个消息ID且不重复；Edge最近20条加更早记录合计22条。

## 实际请求与响应摘录

以下摘自最终HTTP证据，去掉外层timestamp和重复字段，保留真实测试ID。夹具已清理，不能使用这些ID继续请求。

新建`POST /ai/chat/session`，请求`{}`，HTTP200：

```json
{"code":200,"message":"success","data":{"id":105,"title":"新资料会话","mode":"LOCAL_SEARCH","revision":1,"messageCount":0,"lastMessageTime":null,"createTime":"2026-09-29T23:38:56","updateTime":"2026-09-29T23:38:56"}}
```

第一次检索`POST /ai/chat/search`：

```json
{"sessionId":105,"query":"霁澜星径","topK":1,"requestId":"61a9a222-faeb-4176-b6b7-ab63cb1cffc6"}
```

HTTP200/code200，data中的实际关键字段：

```json
{
  "session":{"id":105,"title":"霁澜星径","mode":"LOCAL_SEARCH","revision":2,"messageCount":2},
  "requestId":"61a9a222-faeb-4176-b6b7-ab63cb1cffc6",
  "replayed":false,
  "messages":[
    {"id":419,"role":"user","messageType":"LOCAL_QUERY","content":"霁澜星径","tokensUsed":0,"result":null},
    {"id":420,"role":"assistant","messageType":"LOCAL_RESULT","content":"本地资料检索结果","tokensUsed":0,"costMs":3,
     "result":{"query":"霁澜星径","mode":"LOCAL_NGRAM","matchedAtSearch":true,
       "message":"以下为资料原文片段，请结合来源与更新时间核实",
       "references":[{"docId":36,"chunkId":109,"chunkIndex":1,"title":"KSS_6486d35a28原文旧标题","excerpt":"霁澜星径，旧历史私密片段。<img src=x onerror=\"alert(1)\">","keywordCoverage":1.0,"documentPath":"/knowledge/36","sourcePath":null}],
       "unavailableReferenceCount":0}}
  ]
}
```

同UUID、同query/topK重发：HTTP200/code200、replayed=true，仍为419/420、计数2，不追加消息。改query或topK但复用UUID：HTTP200/code409，message=`此请求编号已用于其他问题，请刷新或提交新的检索`。两个同时提交的相同请求实际返回一首次、一回放且SQL只有一对消息；不同UUID可以分别追加。

资料停用后，同请求回放仍200，但result.references=[]、unavailableReferenceCount=1，提示`部分历史引用已更新或不再公开，已隐藏旧片段，请重新检索`；原标题/正文/链接均不返回。重开同一未修改资料可恢复当前有效引用；编辑正文会更换分片，旧chunk失效，旧历史不映射到新正文。重新检索“晴岚星径”实际返回chunk110和新原文。

无命中“土星雷暴天气”：HTTP200/code200，assistant.content=`本地资料未找到匹配`、matchedAtSearch=false、references=[]，说明换具体地点/关键字，不编造答案。“那里呢”不会自动推断前文。

过期版本重命名/删除：HTTP200/code409，message=`会话已变化，请刷新后重新操作`。缺少删除版本为400；跨用户（含ADMIN）所有详情/历史/修改/删除/检索均404。匿名列表/新建/检索实际HTTP401/code401。

## 所有失败、原因和解决

| 问题 | 实际表现/原因 | 修复与验证 |
|---|---|---|
| 新页面待确认UUID被刷新清空（代码审查发现） | 后端成功但网络响应丢失时，刷新丢掉原requestId，下一次会成为新请求，可能重复记录 | 同会话刷新保留待确认UUID及编辑草稿；只有明确“改为新的检索”才清除。Edge先route.fetch发送真实HTTP取得200，再仅丢弃响应，刷新后重试仍同UUID/同消息ID，SQL消息仅2条 |
| 接口用例UUID复用 | 初测145/146：非法词法query用例借用了已经成功的UUID，实际正确409，测试误期待400 | 每个非法query用新UUID；完整复测146/146；不修改正确的后端冲突语义 |
| 浏览器注册夹具过长 | 初测1/3：测试用户名22字符，已有注册上限20，实际400 | 缩短UUID片段，夹具≤20字符；不放宽已有注册规则 |
| 页面断言先于历史加载 | 第二轮54/55：切回会话先收到详情，历史HTTP未完成便读DOM=0 | 等待20条消息真实渲染，再断言；最终55/55，pageerror=0；不伪造返回或加入固定长睡眠 |
| 环境初始服务未运行 | Redis/后端/Vite未启动，不能立即验收 | 启动回环服务，健康UP后执行；不是业务缺陷 |
| 运行工具输出Unicode编码限制 | Windows Python默认GBK无法打印emoji检查文本 | 只调整检查脚本stdout UTF-8；应用和UTF-8证据不受影响，无证据丢失 |

历史引用下架泄漏属于实现前识别并防护的风险：不把数据库references_json原样返回，所有新检索/历史/幂等回放均重新查询当前资料、来源和索引代次。实际停用、正文修改、路线父目的地下架均验证旧标题/摘录/链接缺失。已经显示在浏览器里的内容需要刷新再核验，本批没有即时下架推送。

## 验收范围、迁移和清理

100会话边界：专属用户SQL准备99条，再真实HTTP创建第100个及拒绝第101个。200轮边界：一轮真实检索+SQL准备398条平衡消息，达到400条后拒绝新UUID，原成功UUID仍可回放。它们是边界夹具验收，不是100会话/200轮全部通过真实调用建立，也不是生产压测。

SQL升级只新增session.mode/revision、message.message_type/request_id/request_hash及2索引，重复执行安全。本机升级前聊天表0行，不能宣称实测保留了大量旧业务聊天；另用本人LEGACY会话/消息夹具重复升级，正文未变且新接口排除LEGACY。新库schema.sql同步，但已有库不执行重建。

最终检查14个本批已注册账号及其数据库/Redis会话无残留、6篇本批知识夹具无残留、孤儿消息0、证据临时写入0；原10篇演示资料仍就绪。回归脚本各自清理专属夹具。未重置共享Redis或全站模型配额，无模型调用与伪造调用日志。

本批未测真实模型、语义向量、跨节点负载、生产长时间数据库规模或聊天token SSE。Edge仅响应丢失用例有网络故障注入，注入前真实服务已成功写入；其他请求没有模拟返回。
