# 邮箱验证与找回密码

更新：2026-10-01。用户要求先完成邮箱验证和找回密码，并明确暂不设置真实 SMTP。功能在 `codex/email-recovery` 独立工作树开发，基点为已核对远程的 main=d63cb66，不依赖尚未融合的资料会话分支。

## 使用

- 注册页可选填写邮箱；填写时必须通过邮件中的6位验证码完成验证。不填写邮箱仍可注册，之后到个人中心验证。
- 个人中心显示当前邮箱及验证状态。验证原邮箱或更换邮箱需输入目标邮箱和当前密码，发送验证码后确认绑定。普通资料保存不能直接更换邮箱。
- 登录页“忘记密码？”进入 `/forgot-password`。输入已验证邮箱、邮件验证码和新密码后重置；8-20位，包含字母与数字。成功后重新登录，各设备旧 access/refresh 令牌均因密码指纹改变而失效。
- 旧库邮箱默认未验证，不能直接用于找回密码。旧账号应先登录验证邮箱；没有已验证邮箱且忘记密码的账号，本批未提供人工恢复流程。
- 发送按钮倒计时、错误提示、草稿保留、确认密码及手机布局已接入。HTTP与邮件正文不包含账号是否存在的信息；有效格式的未知/未验证/停用邮箱也走同一 SMTP 发送路径，验证码不能修改账号。

## 邮件配置

默认 `TRIP_MAIL_ENABLED=false`，未配置时发送接口返回业务503“邮件服务尚未配置”，不预留验证码或发送额度。当前没有配置真实供应商或凭据。

需要启用时通过运行环境提供以下变量，密码使用供应商的 SMTP 授权凭据：

| 变量 | 用途/默认值 |
|---|---|
| TRIP_MAIL_ENABLED | true启用，默认false |
| SMTP_HOST | SMTP服务器 |
| SMTP_PORT | 587；SSL常见465，按供应商要求 |
| SMTP_USERNAME / SMTP_PASSWORD | 登录账号/授权凭据 |
| SMTP_FROM | 发件地址，须与供应商许可一致 |
| SMTP_AUTH | 默认true |
| SMTP_STARTTLS | 默认true，同时要求STARTTLS |
| SMTP_SSL | 默认false；直接SSL时设true并关闭STARTTLS |

连接/读/写超时均为5秒。使用 Spring Boot 官方 JavaMailSender 配置方式：[Sending Email](https://docs.spring.io/spring-boot/reference/io/email.html)。凭据不放前端、Git或验收结果。生产必须关闭可能输出绑定参数的 MyBatis日志，并使用已配置的生产 JWT 密钥。

## 接口契约

统一响应仍为 `{code,message,data,timestamp}`；业务错误通常在HTTP200包内，鉴权失败可为HTTP401。

| 接口 | 请求字段 | 权限/结果 |
|---|---|---|
| POST /auth/email/code | email | 公开，注册验证码 |
| POST /auth/register | 原注册字段；填写email时须emailCode | 验证并创建账号，userInfo新增emailVerified |
| POST /user/email/code | email,password | 本人登录+当前密码，绑定验证码 |
| POST /user/email/verify | email,code | 本人登录，返回最新UserVO |
| POST /auth/password/code | email | 公开，密码恢复验证码 |
| POST /auth/password/reset | email,code,newPassword | 公开，成功data=null，不自动登录 |

新接口严格要求字段和JSON字符串；验证码6位数字字符串，邮箱最长100字符，trim后整体小写，不做加号/点号别名合并。发送成功data包含message、expiresIn=600、retryAfter=60，不返回验证码。400为字段/验证码错误，409为邮箱占用，429为发送频率限制，503为未配置或依赖故障。UserVO的emailVerified为boolean。

## 安全与并发设计

- REGISTER/BIND/RESET隔离，绑定码另按认证用户隔离；Redis键使用邮箱SHA-256，验证码只保存带随机挑战ID的摘要。
- 10分钟有效、单次原子消费，错误5次删除。重发立即覆盖旧码；SMTP失败删除本次挑战并释放本次冷却，但已计入小时预算。暂未就绪的挑战不能消费。
- Redis Lua原子限制同邮箱每60秒1次、每滚动小时5次，来源IP每滚动小时20次，全站每滚动小时100次。三个用途共用发送预算，成功准入时开启小时窗口；依赖Redis故障时拒绝发送/消费。
- 来源IP取Servlet remoteAddr，不信任客户端伪造的转发头。反向代理部署需由服务端配置可信代理，否则代理后的用户共用IP额度。本批只验收单机/普通独立Redis，不支持Redis Cluster多键跨槽。
- 绑定/重置验证码包含用户ID、密码摘要、当时邮箱、验证状态及启停状态快照。密码或邮箱变化使此前挑战失效；停用账号不可恢复。重新绑定邮箱后原邮箱不能找回。
- SQL事务行锁协调重置、邮箱绑定、登录、管理员停用；唯一邮箱索引兜底并发占用。Redis消费独立于SQL事务，若消费后写库失败，验证码不会复活，需重新发送；不声称跨存储分布式事务。
- 密码改变后，现有AuthSessionService每次鉴权都检查数据库密码指纹，旧会话不可恢复；Redis旧会话键等待原TTL清理，不把删除所有键作为正确性前提。
- 未知和已注册邮箱发送时执行同样的SMTP路径及措辞，统一返回错误。采用验证码而非URL令牌，不生成依赖Host头的恢复链接。设计参考[OWASP密码恢复建议](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

## 本地复现

`trip-server/scripts/local_mail_sink.py`仅绑定127.0.0.1，SMTP2527/测试邮箱HTTP8027。它把测试邮件留在进程内，HTTP暴露测试验证码，不能部署到生产。验收使用 `.invalid` 地址，不向真实收件人发送。

1. 启动隔离 Redis6387（关闭持久化）和local_mail_sink.py。
2. 后端运行8087，Redis端口6387，命令行临时启用mail/from，SMTP host=127.0.0.1、port=2527；auth/starttls.enable/starttls.required=false。此设置只用于本地验收，不写进默认配置。
3. 前端设置 `VITE_PROXY_TARGET=http://127.0.0.1:8087`，运行5187端口。
4. 后端执行 `python scripts/email_auth_acceptance.py`；前端执行 `node scripts/email_auth_browser.cjs`。
5. 默认关闭邮件的后端运行8088后，设置TEST_BASE_URL并运行 `email_disabled_acceptance.py`、`basic_user_acceptance.py`。

接口脚本只允许loopback并固定Redis6387；会修改专属测试地址的预算/TTL以分离边界场景，真实10分钟等待通过Redis TTL及强制过期验证。所有临时账号、会话、挑战与测试邮件逐项清理，不清空业务Redis。Maven和前端构建分别运行 `mvn test`、`npm run build`。
