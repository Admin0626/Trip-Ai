## 实际响应及缺陷

### AV-01：合法上传头像保存失败，非法36位名字反而通过

上传返回 `/api/files/9f8632ec45f54d40a1c63330bbdc6c8a.png`，随后 `PUT /user/profile` 请求 `{"avatar":"/api/files/9f8632ec45f54d40a1c63330bbdc6c8a.png"}`。

修复前 HTTP 200，响应摘录（省略 timestamp）：

```json
{"code":400,"message":"头像必须为本站上传路径或 http/https 图片地址","data":null}
```

原因：文件服务生成和读取规则为32位小写十六进制 UUID 加 `.png/.jpg`，资料校验却要求36位且允许短横线、大写和 `.jpeg`。同一规则错误还使无法被文件读取接口服务的36位地址被保存接受。

修复：`UserSettingsService.safeAvatar` 改为 `/api/files/[a-f0-9]{32}\.(png|jpg)`，与生成及读取规则一致。正常 HTTP(S) 外部头像、清空头像仍受支持。

最终 PNG 保存 HTTP 200，业务 code 200，`data.avatar` 为 `/api/files/d795188fa2364f35aea346fd8a229548.png`；随后 GET 与 SQL 均为同一路径。JPEG 对应路径为 `/api/files/455b495b14f145748872423ee706b84e.jpg`，也全部一致。36位、大写、`.jpeg`、目录穿越等本地地址返回业务400。

### AV-02：保存成功后响应仍返回旧头像

仅修复路径后，中间实测：PNG 保存请求的路径为 `/api/files/98ce9a6854c94928a4bdfa58ee626788.png`，响应业务 code 200，但 `data.avatar` 仍为 `""`；再次保存 JPEG 时，响应反而包含上一次 PNG 地址。独立 GET 和 SQL 已是最新值。

原因：事务中先通过 MyBatis 查询用户，随后 JdbcTemplate 直接更新数据库，最后再次执行相同 Mapper 查询。直接 JDBC 写入没有使 MyBatis 会话缓存失效，最终读到之前缓存的用户。前端将保存响应写入 Pinia/localStorage，使顶部头像回到旧值；同一流程也会影响昵称、邮箱等字段。

修复：资料写入改用 `SysUserMapper.update` 与 `LambdaUpdateWrapper`，让 Mapper 写入清除本事务查询缓存，再读取并返回资料。保留原行锁与事务，显式 `set` 每个允许字段，确保空邮箱/手机号可转换为 NULL，部分更新不清掉未传字段。

回归：保存响应、独立 GET、数据库三处头像一致；昵称/城市/邮箱即时响应为新值；单独清空邮箱时昵称保留，数据库 `email IS NULL=1`。浏览器顶部头像和持久化资料随保存更新，重新加载后图片正常解码显示。

## 上传与路径边界

| 场景 | 实际结果 |
|---|---|
| 未登录上传 | HTTP401，code401 |
| PNG/JPEG 实际图片 | HTTP200/code200；文件字节一致，正确 Content-Type，`nosniff` |
| PNG 内容伪装为 JPEG 文件名/MIME | 成功但按实际解码格式保存 `.png` |
| 空文件、伪PNG文本、GIF、截断PNG、缺少 file 表单项 | HTTP200/code400 |
| 6001像素宽、2500万像素 | HTTP200/code400，`图片尺寸过大，请压缩后上传` |
| 恰好 5 MiB（有效PNG加填充） | HTTP200/code200 |
| 5 MiB加1字节 | HTTP200/code400，`图片须非空且不超过5MB` |
| 无效文件名/不存在的合法文件名 | HTTP404 |
| javascript地址、含userinfo的HTTP(S)地址 | 保存返回HTTP200/code400 |
| 普通HTTPS地址、空头像 | 保存成功；HTTPS只测地址保存，不请求外部资源 |

大小门槛按文件本身字节计算，multipart请求还包含表单头。尺寸用构造的PNG头验证“解码像素前拒绝”，没有把大图完整解码。业务校验沿用项目响应约定 HTTP200/code400，未登录使用真实HTTP401；实测同时检查两者。

# 在 trip-server
python scripts/avatar_acceptance.py --label fixed
