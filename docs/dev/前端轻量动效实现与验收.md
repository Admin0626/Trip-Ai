# 前端轻量动效实现、实际验收与答辩复盘

2026-10-04。本批按用户选择的“轻盈自然”程度，沿用现有自然主题。独立分支codex/frontend-motion，起点main=482e2b4。只调整前端交互表现，不修改后端、接口合同、数据库或模型配置，无新增依赖。

## 已实现与入口

| 位置 | 实际行为 |
|---|---|
| 前台/后台页面及旅行助手模式切换 | 淡入并从下方8px上移，220ms；后台没有表格逐行排队 |
| 首页标题、按钮、插画和目的地/路线/我的规划列表 | 进入视口时播放一次280ms；前6项每项错开35ms，最长175ms，其后无额外延迟 |
| 目录卡片、路线卡片、规划卡片 | 精细指针悬停或键盘焦点轻抬3px；阴影即时反馈，不插值动画 |
| 按钮、模式按钮、菜单按钮 | 可操作按钮悬停上移1px，按压下移1px，180ms；禁用/加载态不增加该反馈 |
| 导航与手机菜单 | 导航细线180ms展开，手机菜单180ms淡入 |
| 登录卡片、空状态、AI预览 | 短暂淡入；生成进度标题的小绿点只在busy状态中呼吸，完成/取消/错误后移除 |
| 系统减少动态偏好 | 禁用新动画，取消正在播放与待入场动画；卡片/按钮不位移，状态点静止；恢复偏好后新动画生效 |

路由使用已有容器，不给RouterView添加key或重新挂载表单。旅行助手只在mode值改变时播放入场，不因输入或每次响应更新重播。共享需求在模式切换后保留；原有子页面卸载时清除API Key的行为仍保留。动画结束无残留transform，不遮挡点击或键盘焦点。

## 实现与请求链

- `trip-web/src/directives/motion.ts`注册v-reveal与v-page-enter。IntersectionObserver判断进入视口；Web Animations API播放opacity/transform关键帧；元素卸载、系统偏好变化及应用卸载取消与解绑。
- `trip-web/src/assets/styles/motion.scss`集中按钮/卡片/菜单/状态点规则及减少动态覆盖；`main.ts`安装指令，`index.scss`引入样式。
- UserLayout/AdminLayout在现有main容器绑定路由path；TravelAssistant在原tabpanel绑定mode；Home、RouteList、DestinationList、PlanList与AiPlanner预览使用入场指令。
- 页面仍按原链路调用HTTP或SSE，动画不发起接口请求，不生成伪造进度。没有滚动事件逐帧更新，也没有新动画库。

默认CSS不把内容设为隐藏。没有Animation或IntersectionObserver时跳过对应效果，页面正常显示。取消动画后立即回到可见的原样式。Observer在进入后unobserve，避免反复滚动重播与大列表排队。

## 答辩理解

1. 为什么选择CSS/浏览器API？动画数量有限，原Vue页面只增加指令和共享规则，避免新依赖；transform/opacity更容易保持平滑。
2. 为什么内容默认可见？动画增强体验，浏览器不支持或用户选择减少动态时仍能完成操作。
3. 为什么不用路由key实现淡入？重新挂载会重置页面实例及输入；本批在原容器上播放动画，未保存编辑与共享需求保持原逻辑。
4. 为什么只让前6项错峰？长列表逐项等待会拖慢阅读；后续进入视口即可播放，没有累积延迟。
5. AI点闪动是否代表模型输出？只代表原请求处于busy，文字仍由实际阶段决定；本批不是逐token流式生成，也不把夹具当真实模型。
6. 如何证明不只是加样式？真实Edge中读取运行的动画和样式，实测键盘/鼠标/手机/偏好变化；保留失败轮次和最终截图，再回归原基础工具。
