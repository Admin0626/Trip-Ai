# 统一旅行助手开发与答辩复盘

日期：2026-10-03。用户确认输出形式为“旅行建议文字＋可保存的每日行程”。本批不新增数据库表，不改变路线预约及规划编辑的数据所有权。

## 使用方式

登录后导航点击“旅行助手”。AI定制模式已经预填DeepSeek基础地址https://api.deepseek.com、模型deepseek-flash；填写自己账户的API Key，先测试连接，页面展示模型实际回复。也可填写其他可信兼容服务地址、模型，或localhost/127.0.0.1的高位端口服务。基础地址不要写/chat/completions；不用在Key前写Bearer，已写也会规范化。地址与模型按账号可记住，Key只存在当前页面内存，刷新/切换模式/离开要重新输入。

填写需求、天数、总预算、人数和日期，生成后先阅读中文建议与每日活动，确认后保存到“我的规划”继续编辑。现有SSE展示连接/生成/校验/重试阶段，可取消；上游依然非流式返回完整JSON，这一批没有逐token聊天。查找已有路线模式无需密钥：规则解析→用户修订条件→筛选发布路线→查看详情/预约。其价格筛选是路线人均参考价；AI预算是总预算。只共享需求文字，避免把两种价格条件混用。

## 为什么整合入口但保留两种方式

两者都帮助用户安排旅行，所以在导航上合为一个旅行助手。已有路线方式从数据库选择现成产品，可以预约；AI方式根据用户自己的模型生成新草稿，不能自动宣称为可预订产品。保留方式选择能够说明结果来源，又减少重复入口。/recommend和/ai-planner保留，老书签和既有流程继续可用；统一路径为/travel-assistant，可带mode=routes或mode=ai。

## 关键实现与数据流

TravelAssistant.vue管理选择和共享需求，嵌入Recommend.vue或AiPlanner.vue。切换时卸载原组件，旧请求结果通过既有revision/mounted保护丢弃，模型Key清空；AI忙碌时方式按钮禁用，可用既有取消生成后再切换。AppHeader与Home只展示统一入口，旧URL也激活该导航。

`PlannerConnection`在构造时规范Key且toString脱敏。`PlannerService.reserve`先校验地址，再拦截公网空Key，随后执行既有单用户并发/单实例容量、熔断、Redis配额和审计。test返回connected/model/reply，生成则使用当前启用的数据库USER_PLANNER模板，并附加answer契约。生成JSON校验失败最多重试一次，每次实际上游尝试按原规则计费/计额度；错误不会伪造模型回答。

`CompatiblePlannerClient.requestBody`只有精确api.deepseek.com才添加thinking disabled，结构生成另加response_format json_object。理由来自真实16token探测与[DeepSeek官方思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)及[JSON模式](https://api-docs.deepseek.com/guides/json_mode/)：默认思考可能先用完短连接测试的预算。不能将reasoning_content作为content，也不能把这些厂商扩展发送给所有兼容服务。非流式响应finish_reason=length会明确拒绝，HTTP鉴权/限流/超时、1MiB响应上限与禁止重定向继续保留。

`PlannerOutputValidator.Draft`新增可选answer，最多4000个Java字符，类型必须文本或null；title/dayList/items继续严格校验，忽略模型IDs及归属。旧兼容模型缺answer仍返回可保存每日行程，页面清楚提示未提供独立文字建议。Vue插值以纯文本显示answer，script标签不会执行。没有保存或展示模型思考过程。

保存仍调用已有POST /plan，需要用户另行确认，存title/天数/日期/预算/人数/每日条目；answer只用于当次预览，不承诺永久保存建议全文或聊天历史。不能把model/source/answer等预览字段当成数据库归属。真实测试已经确认生成不自动创建草稿，保存后可读回每日行程。

## 答辩可以这样说明

“系统提供同一旅行助手入口：规则方式匹配可预约的已有路线，模型方式调用用户自己的兼容服务生成个性化草稿。我们修复了DeepSeek默认思考耗尽短测试token导致空最终回复的问题，只针对该供应商配置关闭思考。模型先回答旅行建议，再按固定JSON输出每日安排，后端校验，用户确认后保存。配额、熔断、超时和取消限制外部调用成本，密钥不写入数据库或日志。”

证据是一次真实DeepSeek应用链路16项、受控模型18项、统一入口28项页面及原流程回归，不代表全部模型或任意旅行需求质量都已验证。实时交通、营业和价格仍需用户核实；RAG生成依据、语义向量、多路推荐/重排、评论情感与已有行程就地AI优化另批。主包约1129.27kB构建警告仍待优化。暂无GitHub CI检查，不能称CI通过。
