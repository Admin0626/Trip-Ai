# 后台数据与可视化：实现、实际验收、缺陷与答辩复盘

2026-10-04。独立codex/admin-analytics基于origin/main=482e2b4；上一批动效PR #12未合并，本批不依赖该分支。用户要求后台有柱状图、散点图等，现已增加真实统计接口与`/admin/analytics`页面。

## 功能与使用

ADMIN登录后从“数据与可视化”进入。选择近7/30/90日、目的地并刷新，读取真实业务记录：

- 四项指标：窗口预约单数（附当前取消率）、有效路线数、全站新增用户（附当前总数）、全站模型日志（附成功率与平均耗时）。无分母显示“暂无记录”，不把无调用当100%成功。
- 折线图可切预约创建、新增用户、模型记录，切指标复用同一响应，无额外查询；每天无记录补0。
- 目的地预约Top10水平柱状图；路线参考价与预约单数散点图，含零价和零预约。
- 预约当前状态、模型成功/失败柱状图。零值图形实际宽度0，旁边保留数字0。
- 路线散点明细与可展开的每日明细；键盘Tab/Enter或鼠标查看图形的准确数值。路线最多100点，匹配总数超出时明确提示；目的地选项最多1000，超出时显示数量与范围。
- 加载/失败/空状态独立呈现，失败可重试；筛选变化清除旧快照，AbortController加请求版本检查避免旧响应覆盖。手机单列、坐标布局随实际容器宽度重新计算，避免缩小坐标文字；表格内部水平滚动，页面不横向溢出。

接口完整字段、权限和口径见[API实际合同](../api/05-数据与运营.md)。图表不推断价格与销量的因果关系，参考价不是订单实收；模型日志不是计费或用户操作次数。

## 架构与源码

1. 前端路由/ADMIN守卫 → Analytics.vue选择窗口/目的地 → api/modules/analysis.ts发GET /api/admin/analysis/dashboard。
2. SecurityConfig既有/admin/**管理员鉴权 → AdminAnalysisController参数绑定 → AnalysisService只读REPEATABLE_READ事务。
3. JdbcTemplate查询route_booking、route/destination、sys_user、llm_call_log；按窗口范围绑定参数，预约先聚合再JOIN；填补缺失日期 → 统一R响应。
4. Analytics.vue映射图形数据 → components/admin/AnalyticsChart.vue使用原生SVG绘制轴、折线、柱和圆点 → 悬停/聚焦显示文本，明细表复用同一响应。

无图表库、新依赖、后端模型调用或数据库写入。SVG不使用不可信HTML，业务标签通过Vue文本输出。ResizeObserver仅观察图表尺寸，卸载disconnect；离页中止请求。只返回聚合和目录信息，不含联系人、密码、Key、JWT、提示词或日志错误正文。

统计按北京时间今天和前days-1日的创建时间；取消数按预约当前状态，用户注销影响当前用户总数/增长，历史预约仍保留。含下架目录，排除当前已删除路线或目的地；用户/模型是全站，目的地只影响预约/目录。页面显示快照范围与刷新时间。

## 边界、答辩与后续

- 这是后台实际运营数据页，不是未来1920×1080 `/screen`大屏；没有AI洞察、情感自动分类、用户地域地图、词云、Excel导出、实时SSE或日预聚合。本批不读旧seed统计，不把既有UNKNOWN情感伪装成分类结果。
- 只读实时聚合、手动刷新，不是实时推送。REPEATABLE_READ使同一响应内部一致，但刷新后指标可因新订单/状态/注销变化；不承诺历史冻结报表。没有大规模压测，数据增长需独立做时间索引/预聚合验收。
- 零预约目的地不进入热度Top10；散点包含零预约路线，超过100条只看最高预约样本，图形不能代表全量分布或证明因果。参考价变化时历史订单仍投影到当前参考价。
- 未在本批清空全站真实模型日志验证全库无调用，averageMs=null和“暂无记录”来自实现合同；没有真实模型质量/计费验收。无迁移，前后端同步部署，新接口依赖既有管理员登录与MySQL。

答辩可以按“前端筛选→ADMIN鉴权→窗口边界→真实表聚合→响应快照→SVG→明细核对”讲述。为什么不用冗余热度字段？它可能漂移且无时间窗口。为什么取消曲线不能叫每日取消量？这里按创建日期归组、用当前状态计数，实际取消动作需单独按cancel_time定义。为什么模型记录多于点击数？结构重试也有日志。为什么零数据不是故障？没有记录时应如实显示0或空，不造种子结果。

当前发布状态见[进度](后台数据可视化进度.md)和SESSION，独立分支提交PR，不自动合并；原用户材料、固定v0.1.0-baseline及动效PR #12保留。
