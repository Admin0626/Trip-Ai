### 1.3 表清单补充与勘误

原文档存在两处不一致，**开发时以本节与 `schema.sql` 为准**：

**勘误 1 · 表数量**

表清单标题写「共 20 张」但实际列出 22 张；另有 4 张表在正文中被引用或功能上必需却未进清单，最终确定为 **26 张**：

| 表名 | 来源 / 理由 |
|---|---|
| `llm_call_log` | 原 §8.2「可观测」提到，清单漏了。记录每次调用的模型、token、耗时、是否降级 —— AI 功能的成本与稳定性全靠它 |
| `stat_daily` | 原 §9.3「性能设计」提到预聚合宽表。大屏与 AI 洞察的数据源，**没有它大屏会卡** |
| `user_plan_day` | 规划需要按天命名（`03-前端设计` §4.4 的「第 1 天 · 大理古城」）。与 `route_day` 对称后，「以路线为模板创建规划」可以直连复制 |
| `sys_log` | P2 功能 SYS-11 操作日志需要落库 |

**勘误 2 · `route.status` 取值冲突**

| 出处 | 定义 |
|---|---|
| 原 `01` §7.2 | `0 草稿 / 1 上架 / 2 下架` |
| 原 `04` §6.2 | `0 已下架 / 1 已上架` |

**统一为 `0 下架 / 1 上架`**，理由：接口 `PUT /route/{id}/status` 只做上下架；「草稿」语义用 `status=0`（未发布）表达即可，不额外增加状态位。

**勘误 3 · `route_comment` 与接口路径**

接口路径为 `/interaction/comment`，但实体表名为 `route_comment`，两者保持一致，不要建两张表。

### 1.4 建表约定（全表统一）

| 项 | 约定 |
|---|---|
| 主键 | `id bigint unsigned AUTO_INCREMENT` |
| 字符集 | `utf8mb4` / `utf8mb4_general_ci` |
| 引擎 | InnoDB |
| 审计字段 | 除纯关联表外，统一带 `create_time`、`update_time`（`ON UPDATE CURRENT_TIMESTAMP`） |
| 逻辑删除 | 需要保留痕迹的表加 `deleted tinyint default 0`（`sys_user`、`destination`、`route`、`route_comment`、`feedback`、`user_plan`、`llm_chat_session`、`knowledge_doc`） |
| 计数冗余 | `route` 的 `like_count` 等计数字段由业务侧维护，不使用触发器 |
| 唯一约束 | 点赞/收藏用 `uk(user_id, route_id)` 保证幂等，重复提交直接由数据库拦截 |
| 索引 | 所有外键列建普通索引；列表页筛选列（`status`、`destination_id`、`create_time`）建联合索引 |
| 金额 | 一律 `decimal`，禁止 `float` |
| 标签 | 逗号分隔的 `varchar`，暂不建标签表（P2 再考虑规范化） |

### 1.6 `stat_daily` 指标字典

大屏与 AI 洞察都从这张表读数，`metric_key` 定义如下（每行一个指标，按日期唯一）：

| metric_key | 含义 | 单位 |
|---|---|---|
| `today_visit` | 当日访问量（PV） | 次 |
| `user_total` | 累计用户数（含当日新增） | 人 |
| `new_user` | 当日新增用户 | 人 |
| `route_total` | 在架路线总数 | 条 |
| `booking_count` | 当日预约量 | 单 |
| `booking_cancel` | 当日取消量 | 单 |
| `ai_chat_count` | 当日 AI 问答次数 | 次 |
| `ai_recommend_count` | 当日 AI 推荐次数 | 次 |
| `comment_count` | 当日新增评论数 | 条 |
| `sentiment_positive` | 当日正面评论数 | 条 |
| `sentiment_neutral` | 当日中性评论数 | 条 |
| `sentiment_negative` | 当日负面评论数 | 条 |
| `avg_score` | 当日平均评分 | 分 |
| `llm_tokens` | 当日 token 消耗 | 个 |

`extra_json` 存放无法单值表达的维度数据（如地域分布 TOP5、路线热度 TOP3 的数组），供 AI 洞察 Prompt 使用。
