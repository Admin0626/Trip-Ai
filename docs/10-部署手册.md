# 部署手册

> 目标：把项目从零跑起来，并能稳定演示。
> 适用环境：Windows 开发机 / Linux 服务器（Ubuntu 22.04）
> 关联文档：[`06-工程结构与开发计划.md`](06-工程结构与开发计划.md)、[`api/`](api/)

## 一、环境要求

| 组件 | 版本 | 必需 | 说明 |
|---|---|:--:|---|
| JDK | 17 | ✅ | Spring Boot 3.2 最低要求 17 |
| Maven | 3.8+ | ✅ | 或用 IDEA 内置 |
| Node.js | 18 LTS / 20 LTS | ✅ | Vite 5 要求 18+ |
| MySQL | 8.0 | ✅ | 需支持 `DESC` 索引，5.7 会报错 |
| Redis | 6.0+ | ✅ | 缓存 + 令牌桶限流 |
| Milvus | 2.3+ | ⭕ | RAG 向量库；**没装可先用 Redis-Stack 替代** |
| 大模型服务 | — | ✅ | DeepSeek / 通义千问 API Key，或本地 Ollama |
| Nginx | 1.20+ | ⭕ | 生产部署需要，本地开发不需要 |

**内存建议**：只跑 MySQL + Redis + 后端 + 前端，4GB 够用；加 Milvus 建议 8GB 以上。

## 二、初始化数据库（三步，顺序不能错）

**导入前先自检**（校验列值数是否错位、引号括号是否配对，20 秒能省掉半小时排查）：

```bash
cd trip-server/src/main/resources
python validate_sql.py       # 输出「全部通过，可以导入数据库。」即可继续
```

```bash
mysql -u root -p < trip-server/src/main/resources/sql/schema.sql       # 1. 建库建表（26 张）
mysql -u root -p < trip-server/src/main/resources/sql/seed_config.sql  # 2. 配置种子（推荐权重 + 6 个提示词模板）
mysql -u root -p < trip-server/src/main/resources/sql/data.sql         # 3. 演示数据（可选，但强烈建议执行）
```

| 文件 | 内容 | 能否跳过 |
|---|---|:--:|
| `schema.sql` | 26 张表 + 索引 + 库创建 | ❌ 不能 |
| `seed_config.sql` | 25 条推荐/LLM 配置 + 6 个提示词模板正文 | ❌ 不能，跳过 AI 功能全废 |
| `data.sql` | 21 用户 / 10 目的地 / 80 景点 / 20 路线 / 276 行程项 / 143 评论 / 420 条统计指标 | ⭕ 可跳，但大屏会全空 |

**演示账号**

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `123456` | ADMIN |
| `user1001` ~ `user1020` | `123456` | USER |

> 密码使用 BCrypt 存储，已实测校验通过。若登录失败，用下面这段生成新哈希替换 `sys_user.password`：
> ```java
> System.out.println(new BCryptPasswordEncoder().encode("123456"));
> ```
> ```bash
> python -c "import bcrypt; print(bcrypt.hashpw(b'123456', bcrypt.gensalt(rounds=10, prefix=b'2a')).decode())"
> ```
> ⚠️ 别直接抄网上流传的 `$2a$10$7JB720yubVSZvUI0rEqK/...`，那个的明文是 `admin123`，不是 `123456`。

**重新生成演示数据**：`data.sql` 由脚本生成，改参数后重跑即可（随机种子固定，结果可复现）。

```bash
python trip-server/src/main/resources/generate_data.py
```

## 四、前端启动

```bash
cd trip-web
npm install
npm run dev      # http://localhost:5173
```

`.env.development`：

```
VITE_API_BASE_URL=/api
VITE_PROXY_TARGET=http://localhost:8080
```

**Vite 代理必须为 SSE 关掉缓冲**，否则流式输出会攒一批才吐一次，看起来像卡住：

```ts
// vite.config.ts
server: {
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
      configure: (proxy) => {
        proxy.on('proxyRes', (proxyRes) => {
          if (proxyRes.headers['content-type']?.includes('text/event-stream')) {
            proxyRes.headers['x-accel-buffering'] = 'no';
          }
        });
      }
    }
  }
}
```

## 五、可选组件

### 5.1 Milvus（RAG 向量库）

```bash
wget https://github.com/milvus-io/milvus/releases/download/v2.3.3/milvus-standalone-docker-compose.yml -O docker-compose.yml
docker compose up -d
```
启动后 `localhost:19530` 可连。首次使用在后台「AI 配置 → 知识库」点「重建索引」。

**不想装 Milvus 的替代方案**：把 `trip.llm.vector-store` 改成 `redis-stack`，用 Redis 自带的向量索引能力，少一个中间件，代价是数据量大时召回质量略降。毕设演示规模完全够用。

### 5.2 Docker Compose 一键起中间件

```yaml
# docker-compose.yml
services:
  mysql:
    image: mysql:8.0
    ports: ["3306:3306"]
    environment:
      MYSQL_ROOT_PASSWORD: 123456
      MYSQL_DATABASE: trip_llm
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci
    volumes:
      - ./trip-server/src/main/resources/sql:/docker-entrypoint-initdb.d   # 首次启动自动执行三个 sql
      - mysql-data:/var/lib/mysql
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
    command: redis-server --appendonly yes
volumes:
  mysql-data:
```

> 用 `docker-entrypoint-initdb.d` 时注意文件按**文件名字母序**执行：`data.sql` → `schema.sql` → `seed_config.sql`，顺序反了会失败。建议改名加数字前缀：`01-schema.sql`、`02-seed_config.sql`、`03-data.sql`。

### 5.3 本地 Ollama（完全免费，但需要显卡）

```bash
ollama pull qwen2.5:7b
```

`application-llm.yml` 改 `base-url: http://localhost:11434/v1`，`api-key` 随便填。**7B 模型在意图解析这类结构化任务上表现明显弱于在线模型**，建议只在实在没有 API 预算时使用。

## 六、生产部署（Nginx + systemd）

### 6.1 前端构建

```bash
cd trip-web
npm run build          # 产物在 dist/
sudo cp -r dist/* /var/www/trip/
```

### 6.2 Nginx 完整配置

```nginx
server {
    listen 80;
    server_name travel.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name travel.example.com;

    ssl_certificate     /etc/nginx/ssl/travel.crt;
    ssl_certificate_key /etc/nginx/ssl/travel.key;

    root /var/www/trip;
    index index.html;
    client_max_body_size 20m;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1k;

    # 静态资源长缓存（文件名带 hash）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 普通接口
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 10s;
        proxy_read_timeout    60s;
    }

    # ⚠️ SSE 接口必须单独配置，否则流式输出会被 Nginx 缓冲成一坨
    location ~ ^/api/(ai/recommend/(itinerary|one-shot)|ai/chat/ask|plan/\d+/ai-optimize|analysis/realtime)$ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_http_version 1.1;
        proxy_set_header Connection        '';
        proxy_buffering    off;          # 关键
        proxy_cache        off;          # 关键
        proxy_read_timeout 300s;         # 要大于服务端 120s 超时
        chunked_transfer_encoding on;
        add_header X-Accel-Buffering no; # 关键
    }

    # 上传文件
    location /files/ {
        alias /opt/trip/uploads/;
        expires 30d;
    }
}
```

### 6.3 后端 systemd 服务

```ini
# /etc/systemd/system/trip-server.service
[Unit]
Description=Trip LLM Server
After=network.target mysql.service redis.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/trip
EnvironmentFile=/opt/trip/env            # 存放 DEEPSEEK_API_KEY 等密钥，chmod 600
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -jar /opt/trip/trip-server-1.0.0.jar --spring.profiles.active=prod
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now trip-server
sudo journalctl -u trip-server -f        # 看日志
```

## 七、大屏投放

大屏路由 `/screen`，设计基准 1920×1080，运行时按窗口尺寸 `transform: scale` 自适应。

| 场景 | 做法 |
|---|---|
| 答辩演示 | 浏览器打开 `/screen`，按 `F11` 全屏；投屏分辨率设为 1920×1080 效果最好 |
| 展示大屏 | Chrome 启动参数 `--kiosk --app=https://travel.example.com/screen`，开机自启 |
| 验证自适应 | 分别在 1366×768 和 2560×1440 下检查：无滚动条、无元素溢出（验收标准 INS-12） |

**大屏数据依赖**：核心指标和图表读 `stat_daily` 表，AI 洞察读 `ai_insight` 表。两者都由定时任务写入：

| 任务 | 时间 | 写入 |
|---|---|---|
| 日指标预聚合（INS-15） | 每日 01:30 | `stat_daily` |
| AI 洞察生成（INS-09） | 每日 02:00 | `ai_insight` |

> 演示前一天务必确认这两个任务跑过。`data.sql` 已经预置了 30 天指标和 2 天洞察，即使定时任务没跑，大屏也不会空。

## 八、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| **SSE 不流式，内容一次性出现** | Nginx / Vite 代理缓冲了响应 | 按 6.2 的 SSE 段配置 `proxy_buffering off`，并在响应头加 `X-Accel-Buffering: no` |
| 跨域报错 | 前端直连后端未走代理 | 开发用 Vite 代理；生产用 Nginx 同域反代；不要靠 `@CrossOrigin("*")` 糊 |
| 接口返回中文乱码 | 库或表字符集不是 utf8mb4 | `ALTER DATABASE trip_llm CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;` 后重建表 |
| 时间差 8 小时 | JDBC URL 缺 `serverTimezone` | URL 加 `serverTimezone=Asia/Shanghai`，Jackson 配 `time-zone: Asia/Shanghai` |
| 建表报 `DESC` 语法错 | MySQL 版本低于 8.0 | 升级到 8.0，或把 `heat DESC` 改成 `heat` |
| 登录返回 1001 用户名或密码错误 | 密码哈希不对 | 见第二节的哈希生成命令，重新生成后 UPDATE |
| AI 接口返回 3001 | LLM 不可用或已降级 | 查 `llm_call_log` 的 `error_msg`；确认 API Key 与网络；接口本身应返回降级结果而不是报错 |
| AI 接口返回 429 | 触发限流配额 | 查 `recommend_config` 里的 `llm.user.quota.*`，演示时可临时调高 |
| 推荐结果为空 | 召回无候选 | 确认 `data.sql` 已执行（路线数应为 20）；确认 `preferenceTags` 与 `route.tags` 有交集 |
| 问答总是「没有相关资料」 | 知识库没建索引 | 后台「AI 配置 → 知识库」点「重建索引」，确认 `knowledge_doc.index_status = 2` |
| 大屏图表空白 | `stat_daily` 无数据 | 执行 `data.sql`，或手动触发预聚合任务 |
| 上传图片 404 | 上传目录未映射 | 检查 `trip.upload.local-path` 与 Nginx `location /files/` 的 `alias` 是否一致 |

## 十、备份与恢复

```bash
# 备份
mysqldump -u root -p --single-transaction --routines trip_llm > trip_llm_$(date +%Y%m%d).sql

# 恢复
mysql -u root -p trip_llm < trip_llm_20260919.sql
```

上传的图片目录 `uploads/` 一并打包备份。提示词模板的修改都会入库，所以备份数据库就等于备份了提示词的当前状态。
