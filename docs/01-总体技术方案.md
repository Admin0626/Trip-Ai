# 基于 LLM 的旅行行程推荐系统 — 总体技术方案

> 版本 v1.1 ｜ 技术栈：Spring Boot 4 + Vue 3 + LLM（由 Django 方案迁移而来）
> 编制日期：2026-09-16

---

## 一、项目概述

### 1.1 系统定位

面向自助游用户的**智能行程规划与推荐平台**，以 LLM（大语言模型）作为核心推荐引擎与决策助手，同时为管理员提供数据运营与可视化洞察能力。

### 1.2 交付形态

| 形态 | 使用角色 | 说明 |
|---|---|---|
| 用户端 Web 站点 | 游客 / 普通用户 | 路线浏览、自主规划、AI 推荐、旅游问答、个人中心 |
| 管理后台 | 管理员 | 用户、目的地、路线、互动、轮播图、反馈、推荐配置 |
| 数据可视化大屏 | 管理员 | AI 驱动的运营洞察，全屏投放 |

### 1.3 角色定义

- **ADMIN 管理员**：管理用户、旅游目的地、旅游路线数据；维护路线点赞 / 收藏 / 预约 / 评论信息；管理首页轮播图、用户反馈、推荐系统相关配置。
- **USER 普通用户**：进入个人中心，浏览路线列表，自主进行路线规划，获取智能行程推荐，使用旅游路线问答功能，提交系统反馈。
- **GUEST 游客**（未登录）：可浏览路线列表与详情、目的地，触发登录后可交互。

## 二、技术栈迁移说明（Django → Spring Boot）

### 2.1 逐项对照表

| 能力域 | 原 Django 方案 | 新 Spring Boot 方案 | 迁移要点 |
|---|---|---|---|
| Web 框架 | Django 4.x + DRF | **Spring Boot 4.0.8（Java 17）** | 视图层改为 Controller → Service → Mapper 三层 |
| ORM | Django ORM | **MyBatis-Plus 3.5** | 表结构保持兼容，用 `@TableName` / `@TableField` 映射 |
| 认证鉴权 | simplejwt | **Spring Security 7 + JJWT 0.12.6** | 无状态 JWT + 过滤器链 + `@PreAuthorize` 注解鉴权 |
| 参数校验 | DRF Serializer | **Jakarta Validation** + 自定义校验器 | `@Valid` + `@NotBlank` 等注解 |
| 接口文档 | drf-yasg | **SpringDoc OpenAPI 3 + Knife4j** | 访问 `/api/doc.html` |
| 缓存 | Django Cache | **Redis + Spring Cache** | 路线详情、热门榜单、大屏聚合结果 |
| 异步任务 | Celery + Redis | **@Async 线程池 + @Scheduled**（可升级 XXL-JOB） | 情感分析批处理、大屏数据预聚合 |
| LLM SDK | openai-python | **Spring AI 2.0** | Prompt 工程与向量检索设计完全保留 |
| 向量检索 | faiss + langchain | **Milvus / Redis-Stack**（演示推荐复用 Redis） | RAG 知识库 |
| 流式输出 | Django Channels (SSE) | **Spring MVC `SseEmitter`** | AI 推荐、问答的逐字输出 |
| 文件存储 | Django Storage | 本地磁盘 + 阿里云 OSS | 目的地 / 路线图片、头像 |
| 前端 | Vue 2 + 模板渲染 | **Vue 3 + Vite + TS + Element Plus + ECharts** | 完全前后端分离 |
| 管理后台 | Django Admin | **Vue 3 自研后台** | 风格统一、可定制 |
| 可视化 | matplotlib 静态图 | **ECharts 5 + DataV** | 可交互大屏 |

### 2.2 保留的大模型技术栈（核心不变）

1. **Prompt 工程体系**：意图解析模板、行程生成模板、数据洞察模板，均通过数据库配置化管理。
2. **RAG 检索增强**：目的地 / 路线 / 攻略切片入库 → 向量召回 → 拼装上下文 → LLM 生成。
3. **结构化输出**：LLM 返回 JSON Schema，服务端校验并重试。
4. **流式生成**：SSE 推送，前端逐字渲染，提升体验。
5. **LLM 重排（Rerank）**：传统推荐算法召回 → LLM 对候选做语义重排与理由生成。

## 三、总体架构

采用经典五层架构 + AI 能力独立分层：

```
┌──────────────────────────────────────────────────────────────┐
│ 展示层  Vue3 SPA（用户端 / 管理后台 / 可视化大屏）             │
└──────────────────────────────────────────────────────────────┘
                            ↓ HTTP / SSE
┌──────────────────────────────────────────────────────────────┐
│ 接入层  Nginx → Spring Security(JWT) → 统一响应/异常/日志切面  │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ 业务层  user | destination | route | interaction | plan       │
│         analysis | admin                                      │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ AI 能力层  IntentParser | HybridRecommender | RankLLM         │
│            RagChatService | InsightService | SentimentService │
└──────────────────────────────────────────────────────────────┘
                            ↓
┌──────────────────────────────────────────────────────────────┐
│ 数据层  MySQL 8.0 | Redis | Milvus/Redis-Stack(向量) | OSS(文件)          │
└──────────────────────────────────────────────────────────────┘
```

**关键技术决策**

| 决策点 | 选择 | 理由 |
|---|---|---|
| 前后端分离 | Vue3 SPA + RESTful | 便于大屏、移动端复用同一套接口 |
| 认证方案 | 无状态 JWT | 无需 Session 共享，易于横向扩展 |
| 流式协议 | SSE（非 WebSocket） | 单向推送足够，实现简单、兼容性好 |
| 推荐架构 | 多路召回 + LLM 重排 | 纯 LLM 排序成本高、不稳定；纯 CF 冷启动差 |
| AI 降级 | 规则引擎兜底 | 大模型超时/失败时保证系统可用 |

## 五、功能模块清单

### M1 用户与认证模块
- 注册、登录（账号密码）、JWT 签发与刷新、退出登录
- 个人资料维护（昵称、头像、手机号、所在城市）
- 旅行偏好设置（偏好标签：自然风光/历史文化/美食/亲子/摄影/探险；预算区间；出行天数）
- 修改密码、找回密码（邮箱验证码）
- 用户行为埋点记录（浏览、点赞、收藏、预约、搜索关键词）→ 供推荐算法使用

### M2 目的地管理模块
- 目的地 CRUD（名称、所属省市、经纬度、封面图、简介、标签、热度值、状态）
- 目的地按省份 / 标签 / 热度筛选与搜索
- 目的地详情（关联路线数、平均评分、热度趋势）
- 景点（Attraction）子资源管理，归属目的地，供行程规划时选择

### M3 路线与行程管理模块
- 路线 CRUD（标题、封面、目的地、天数、价格、难度、标签、行程亮点、注意事项、状态：草稿/上架/下架）
- 行程明细：`route_day`（第 N 天）+ `route_item`（时间点、景点、活动、交通、住宿、用餐）
- 路线列表（分页 + 多条件筛选 + 排序：热度/最新/价格/收藏数）
- 路线详情（含行程 Timeline、点赞/收藏/预约按钮、评论区）
- 路线上下架、置顶、推荐位设置

### M4 互动模块
- **点赞**：路线点赞/取消，记录 `route_like`
- **收藏**：收藏/取消，记录 `route_favorite`，个人中心可见
- **预约**：用户提交预约（出行日期、人数、联系人、备注），管理员审核（待确认/已确认/已取消/已完成）；路线可设置最大预约人数与截止日期
- **评论**：对路线发表评论、评分（1-5 星）、回复、点赞评论；管理员审核与删除
- 后台维护：按路线查看点赞数、收藏数、预约列表、评论列表；支持批量导出

### M5 自主路线规划模块
- 用户选择目的地 → 勾选景点 → 拖拽排序 → 按天分配 → 设置交通/住宿 → 生成个人路线
- 支持草稿保存、继续编辑、复制他人路线为模板
- 保存后可一键「让 AI 优化这条路线」（调用 LLM 给出优化建议）
- 规划结果可导出为文字行程单

### M6 ★ AI 智能行程推荐模块（创新点）
- 用户以自然语言描述需求：「我想 10 月去云南玩 5 天，预算 3000 左右，喜欢自然风光和美食，不要太赶」
- **Step 1 意图解析**：LLM 将自然语言转成结构化 JSON（目的地、天数、预算、偏好标签、同行人、节奏、季节）
- **Step 2 多路召回**：协同过滤（Item-CF）+ 内容相似（标签/目的地匹配）+ 热度召回，融合得候选集（Top 50）
- **Step 3 LLM 重排**：把候选摘要 + 用户意图交给 LLM 打分排序，输出 Top 5 及推荐理由
- **Step 4 行程生成**：对选中的路线，LLM 按天生成细化行程（景点顺序、时间安排、餐饮建议、交通方式），SSE 流式返回
- **Step 5 可解释性**：输出「为什么推荐给你」的理由；支持一键收藏 / 一键据此创建个人规划

### M7 ★ AI 旅游问答模块（创新点）
- 基于 RAG 的领域问答：知识库 = 目的地介绍 + 路线攻略 + 景点贴士 + 常见问题
- 流程：问题 → Embedding → 向量召回 Top-K 片段 → 拼装 Prompt → LLM 流式作答
- 多轮对话，会话与消息持久化，用户可查看历史会话
- 答案附带引用来源（命中的路线 / 目的地），可点击跳转
- 管理员可管理知识库文档（上传 / 切片 / 重建索引）

### M8 ★ AI 数据分析与可视化大屏模块（创新点）
- **数据聚合**：按日/周/月统计路线热度、预约量、用户增长、地域分布、评分分布、标签分布
- **LLM 数据洞察**：把聚合后的结构化数据喂给 LLM，生成自然语言运营解读（如「本周『云南 5 日游』预约量环比上升 42%，主要来自华东地区，建议加大首页轮播曝光」）
- **评论情感分析**：批量分析评论情感倾向（正面/中性/负面）+ 关键词抽取，形成「口碑雷达」
- **可视化大屏**：全屏可投放，含核心指标卡、趋势折线、热度榜单、地域分布、情感占比、标签词云、实时动态流

### M9 运营管理模块
- **轮播图管理**：图片、标题、跳转链接、排序、启用状态、生效时间
- **用户反馈管理**：用户提交反馈（类型/标题/内容/图片/联系方式）→ 管理员查看、回复、标记处理状态（待处理/处理中/已解决）
- **推荐系统配置**：各路召回权重（协同过滤/内容/热度/LLM 重排权重）、LLM 参数（模型、温度、Top-K、超时）、开关（是否启用 LLM 重排）、每日 AI 调用配额
- **提示词模板管理**：模板编码、名称、场景、内容（含占位符）、版本、启用状态，支持在线编辑与回滚
- **操作日志**：记录管理员关键操作

## 六、创新点设计详解

### 6.1 NL2JSON 意图解析
- 输入：用户自由文本
- 输出：强约束 JSON（用 JSON Schema 校验）

```json
{
  "destinations": ["云南"],
  "days": 5,
  "budget": 3000,
  "budgetLevel": "medium",
  "preferenceTags": ["自然风光", "美食"],
  "companions": "couple",
  "pace": "relaxed",
  "travelMonth": 10,
  "mustVisit": [],
  "avoid": ["高原徒步"]
}
```

- 失败兜底：JSON 解析失败自动重试 1 次；仍失败则退化为关键词抽取（正则 + 词典）。

### 6.2 混合推荐 + LLM 重排

| 召回通道 | 算法 | 权重（可配置） |
|---|---|---|
| 协同过滤 | Item-CF，基于用户收藏/预约共现矩阵 | 0.30 |
| 内容相似 | 标签 + 目的地 + 天数 + 预算余弦相似 | 0.35 |
| 热度召回 | 近 30 天点赞/收藏/预约加权得分 | 0.20 |
| 行为召回 | 用户历史浏览序列 | 0.15 |

归一化加权 → 取 Top 50 → LLM 重排（带用户意图 Prompt）→ Top 5。

**LLM 重排 Prompt 结构**：系统角色定义 + 用户意图 JSON + 候选路线摘要列表 + 输出格式约束（JSON Array，含 routeId / score / reason）。

### 6.3 流式行程生成 + 可解释推荐
- 后端用 `SseEmitter`，前端用 `EventSource` / `fetch` 流式读取
- 事件类型：`intent`（解析结果）→ `recall`（候选列表）→ `token`（逐字）→ `done`（完整结构化结果）
- 推荐理由强制出现在答案中，解决推荐系统「黑盒」问题

### 6.4 RAG 旅游问答
- 知识切片策略：按 300~500 字 + 50 字重叠
- Embedding：`text-embedding-3-small` 或 `bge-m3`（可本地部署）
- 召回后做相似度阈值过滤，低于阈值时诚实回答「知识库暂无相关内容」
- 引用溯源增强可信度

### 6.5 LLM 数据洞察（图表的「自然语言旁白」）
- 定时任务每日 02:00 聚合指标 → 生成洞察文本 → 存 `ai_insight` 表
- 大屏右下角固定展示「AI 今日洞察」卡片
- 支持管理员在后台手动触发重新生成

### 6.6 评论情感分析 + 口碑雷达
- 新评论入库后异步触发情感分析，结果写入 `route_comment.sentiment`（positive/neutral/negative）与 `sentiment_score`
- 大屏展示情感占比环形图 + 负面评论关键词 TOP10，帮助管理员定位问题路线

### 6.7 可视化大屏
技术选型：Vue3 + ECharts 5 + DataV（边框 / 装饰）+ 自适应缩放（`transform: scale` 适配不同分辨率，设计基准 1920×1080）。

## 七、LLM 工程化设计

### 7.1 分层设计

```
Controller
   ↓
AiFacadeService          ← 统一入口：限流、配额、日志、降级
   ↓
┌──────────────┬──────────────┬──────────────┬──────────────┐
│ IntentParser │ RankLLM      │ RagChat      │ Insight       │
└──────────────┴──────────────┴──────────────┴──────────────┘
   ↓
LlmClient (Spring AI ChatClient)  ← 模型无关，可换 DeepSeek/Qwen/OpenAI/本地 Ollama
   ↓
Redis（缓存 + 令牌桶限流） / prompt_template（模板来源）
```

### 7.2 关键工程措施

| 关注点 | 措施 |
|---|---|
| 模型可切换 | 配置文件定义 provider，`application-llm.yml` 中集中管理 |
| 超时控制 | 连接 5s / 读取 60s，重试 1 次（指数退避） |
| 结构化输出 | 强制 `response_format=json_object` + JSON Schema 校验 + 失败重试 |
| 流式输出 | SseEmitter，超时 120s，心跳 15s 防断连 |
| 成本控制 | Redis 令牌桶限流 + 每日配额 + 相同请求结果缓存（TTL 10min） |
| 降级策略 | LLM 不可用 → 意图解析退化为关键词规则；重排退化为权值得分；问答返回「AI 服务繁忙」+ 推荐列表兜底 |
| 可观测 | 记录每次调用的模型、token 消耗、耗时、成功状态到 `llm_call_log` |
| 安全 | 提示词注入防护（用户输入隔离在 `<user_input>` 标签内）；敏感词过滤 |

### 7.3 Spring AI 调用示例骨架

```java
@Service
@RequiredArgsConstructor
public class IntentParserService {

    private final ChatClient chatClient;
    private final PromptTemplateService promptService;

    public TravelIntent parse(String userInput) {
        String tpl = promptService.get("INTENT_PARSE");
        String prompt = tpl.replace("{userInput}", sanitize(userInput));
        String json = chatClient.prompt()
                .user(prompt)
                .options(ChatOptions.builder()
                        .model("deepseek-chat")
                        .temperature(0.2)
                        .responseFormat("json_object")
                        .build())
                .call()
                .content();
        return JsonUtils.parseWithRetry(json, TravelIntent.class);
    }
}
```
