## 用户自定义模型规划 `/ai/planner`（已实现，均需登录）

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/ai/planner/options` | 返回allowedHosts与allowLoopback，供页面显示可连接范围 |
| GET | `/ai/planner/usage` | 当前用户小时/日、全局日配额及当日模型操作统计，不接受他人用户ID |
| POST | `/ai/planner/test` | 真实短对话测试连接，不保存Key |
| POST | `/ai/planner/generate` | 返回经过结构校验的行程预览，不直接保存 |

配额已实现：默认20次/用户小时、200次/用户日、2000次/全站日，北京时间固定窗口；测试连接及每一次生成尝试各计1次，结构重试额外扣次。配额拒绝为HTTP200/code429，Redis或配置不可用为HTTP200/code503。规则意图/匹配不扣模型额度。usage的quota包含hourly/daily/globalDaily，每项包含limit/used/remaining/resetAt；today包含operations/succeeded/failed/averageCostMs。实际响应及统计口径见[配额实测](../dev/AI配额与统计接口实测.md)、[开发复盘](../dev/AI配额与统计开发复盘.md)。

管理员`GET /admin/ai/recommend/log`已实现：ADMIN权限，current默认1（1—1000000）、size默认20（1—100）、可选正整数userId，返回PageResult，按id倒序；字段仅id/userId/scene/model/costMs/success/isFallback/createTime，不返回输入或上游正文。普通用户HTTP403，非法分页HTTP200/code400。其他后台AI配置接口仍按后文设计契约，不能据此视为已实现。

连接测试请求：

```json
{"connection":{"baseUrl":"http://localhost:11434/v1","model":"用户自己的模型ID","apiKey":""}}
```

模型ID须为ASCII字母数字及`._:/-`组合、≤50字符；Key可空（无鉴权本机服务），≤512个可打印ASCII字符。URL≤500字符，不含userinfo、query或fragment，后端追加`/chat/completions`；限制见[使用说明](../dev/用户自定义AI规划使用与开发文档.md)。测试成功data为`{"connected":true,"model":"..."}`，不保证该模型一定能生成符合结构的旅行规划。

生成请求增加query（JSON字符串5—1000字符，strip后≥5）、days（JSON整数1—14）、budget（JSON数字0.01—1000000）、peopleNum（JSON整数1—10）、可选startDate（yyyy-MM-dd，今天及以后，省略默认今天）。

```json
{
  "connection":{"baseUrl":"http://localhost:11434/v1","model":"qwen-example","apiKey":""},
  "query":"去大理旅行，喜欢自然风光，带父母，不要太赶",
  "days":3,"budget":3000,"peopleNum":2,"startDate":"2026-10-01"
}
```

`qwen-example`仅为结构示例，须替换成服务实际模型ID；日期也须按当前日期填写。成功data结构为`{draft:{title,dayList:[{dayIndex,title,summary,items:[...]}]},source:"USER_MODEL",model,attempts}`。item只保留已校验的title/timePoint/activity/transport/hotel/meal/tips/cost；attractionId固定0，sortNo按顺序生成。每天1—8项，天数必须一致；未知费用null。attempts为1或2，只有输出结构不合格才自动重试，认证失败/网络错误不自动重试。

code3004表示模型认证、限流、超时、响应过大、格式不合格或模板未初始化，返回安全提示，不返回供应商原始错误正文。code429表示本用户已有进行中的调用或单进程8个并发名额已满。业务错误沿用HTTP200包装，匿名HTTP401。默认每次模型请求45秒，最多两次；响应≤1MiB，禁重定向。

前端显式确认后另外调用已有`POST /plan`保存status=0草稿；生成接口没有数据库规划写入权限。支持新规划生成，原`/plan/{id}/ai-optimize`仍是未实现占位，不能混用。模型调用日志不含Key/地址/需求/完整响应，token默认0表示未采集，非零费用保证。详见[实际验收](../dev/用户自定义AI规划实测.md)。

**POST /ai/recommend/intent**

请求：
```json
{ "query": "我想 10 月去云南玩 5 天，预算 3000 左右，喜欢自然风光和美食，不要太赶" }
```

当前规则模式响应的 `data`（外层仍为统一的 code/message/data/timestamp）：
```json
{
  "intent": {
    "destinations": ["云南"],
    "days": 5,
    "budget": 3000,
    "budgetLevel": "medium",
    "preferenceTags": ["自然风光", "美食"],
    "companions": null,
    "pace": "relaxed",
    "travelMonth": 10,
    "mustVisit": [],
    "avoid": []
  },
  "confidence": 0.3,
  "source": "RULE_FALLBACK"
}
```
`source`：LLM / RULE_FALLBACK（降级标识）

当前实现始终为 `RULE_FALLBACK`。未提取到信息时confidence为0.1，否则0.3，均需用户确认；不是概率估计。query必须是JSON字符串，原始长度不超过500，去除首尾空白后不少于5（Java UTF-16字符计数）。不合格请求按现有业务协议返回HTTP 200、code=400；未登录为HTTP 401、code=401。超长输入明确拒绝，不静默截断；这是当前子阶段对BR-AIC-01“截断并提示”的实施差异，后续前端需展示校验提示。

规则只提取明确的阿拉伯数字天数、预算、月份和词表关键词；中文数字、相对日期、复杂否定和景点语义暂不支持，mustVisit保留空列表。区间与矛盾数字置null。目的地来自数据库在架词表，最多3个；正向标签最多5个。测试边界与证据见 [接口实测](../dev/第3批意图降级接口实测.md)。

**POST /ai/recommend/match**

请求：
```json
{ "intent": { "destinations": ["云南"], "days": 5, "budget": 3000, "preferenceTags": ["自然风光"], "avoid": ["购物"] }, "topN": 5 }
```

基础模式响应data的结构示例（具体路线以数据库为准，非模型结果）：
```json
{
  "totalCandidates": 1,
  "recallDetail": { "cf": 0, "content": 1, "hot": 0, "behavior": 0 },
  "costMs": 12,
  "source": "RULE_BASED",
  "unsupportedCriteria": [],
  "list": [
    {
      "routeId": 201,
      "title": "云南大理丽江香格里拉 5 日纯玩",
      "coverImg": "https://oss.../r201.jpg",
      "destinationName": "云南",
      "days": 5,
      "price": 2980.00,
      "tags": ["自然风光", "摄影"],
      "recallScore": 1.0,
      "llmScore": null,
      "reason": "目的地符合、天数一致、人均参考价在预算内、自然风光",
      "highlightMatch": ["目的地符合", "天数一致", "人均参考价在预算内", "自然风光"]
    }
  ]
}
```

基础匹配规则：

- intent必须是对象；空对象允许按用户评分浏览在架路线。topN省略或null时为5，仅接受1—20的JSON整数。
- destinations可省略/null/空数组，最多3项，去重后精确匹配目的地名称、省份或城市，多项取OR；未知目的地返回空集，不擅自放宽条件。每项1—100字符，去除首尾空白。
- days可空，整数1—365，完全匹配；budget可空，整数1—1000000，对比人均路线参考价上限，包含等于边界。数字字符串、浮点数、布尔值均不接受。
- preferenceTags最多5项，avoid最多16项，均限设计中的16个标签、去重；重叠返回code400。偏好只影响排序，排除标签是硬过滤。数据库标签按逗号完整项匹配，避免把“美食街”认作“美食”。
- 路线与所属目的地都必须上架且未逻辑删除。按偏好命中数降序、平均用户评分降序、路线ID升序返回topN；totalCandidates为截断前的筛选数量。
- recallScore是命中偏好数/去重偏好数，无偏好时为0；不是模型分数或概率。llmScore始终null，source为RULE_BASED；cf/hot/behavior计数为0，仅有content召回。
- 其余非空intent字段返回于unsupportedCriteria，例如companions、pace、travelMonth、mustVisit、budgetLevel，不参与筛选。页面固定说明尚未支持的条件，不宣称全部理解。
- 无结果返回HTTP200/code200及空list；无效参数HTTP200/code400；匿名HTTP401/code401。匹配过程不调用模型、不写模型调用日志。

前端入口 `/recommend`：登录后输入需求→规则解析→用户可编辑目的地、天数、预算、偏好和排除标签→显式确认→查看路线详情。修改需求会废弃旧解析，修改条件会清空旧结果，过期的异步响应不会覆盖当前条件。参见[基础推荐实测](../dev/第3批基础推荐接口与页面实测.md)。

## SSE 接入约定

| 项 | 约定 |
|---|---|
| 请求方式 | `POST` + `fetch` 流式读取（原生 EventSource 不支持自定义头，故用 fetch + ReadableStream） |
| 响应头 | `Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no` |
| 事件类型 | `start` / `intent` / `recall` / `token` / `references` / `error` / `done` |
| 心跳 | 每 15s 发送 `: heartbeat` 注释行 |
| 超时 | 服务端 120s，前端 130s 未收到 `done` 则主动断开并提示重试 |
| 错误 | 发送 `event: error` + `data: {"code":3001,"message":"AI 服务暂时不可用，已为你切换到基础推荐"}` |
| 取消 | 前端 AbortController 中断，服务端检测连接断开后停止生成 |

前端调用示例：
```ts
export function ssePost(url: string, body: any, handlers: Record<string, (d: any) => void>) {
  const ctrl = new AbortController();
  fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${getToken()}` },
    body: JSON.stringify(body),
    signal: ctrl.signal
  }).then(async res => {
    const reader = res.body!.getReader();
    const decoder = new TextDecoder();
    let buf = '';
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      buf += decoder.decode(value, { stream: true });
      const blocks = buf.split('\n\n');
      buf = blocks.pop() || '';
      for (const block of blocks) {
        const event = /event: (\w+)/.exec(block)?.[1] || 'message';
        const data = /data: (.*)/.exec(block)?.[1];
        if (data) handlers[event]?.(JSON.parse(data));
      }
    }
  });
  return () => ctrl.abort();
}
```
